# 제로클리닉 관리자 화면 정찰 (2026-09-09)

`--board-inspect` 를 `https://www.zeroclinic1.com/admin/board/main.php` 로 실행한 결과입니다.
**로그인 단계에서 막혀 목록·글쓰기 폼까지는 들어가지 못했습니다.** 그래서
`inspect.json` 은 만들어지지 않았고(코드가 login → 목록 → 글쓰기 순서로 떠서
로그인에서 예외가 나면 뒤 단계와 리포트 저장까지 못 감), 남은 산출물은 로그인
실패 시점의 스크린샷·HTML 뿐입니다.

## 요약 (한 줄)

로그인 폼·셀렉터·드라이버 로직은 실제 화면과 **맞습니다**. 실패 원인은 두 가지로,
① 서버가 제공된 관리자 **비밀번호를 거부**했고(아이디는 유효), ② 이 실행 환경의
프록시가 Chromium 의 기본 TLS(1.3) 핸드셰이크를 끊어서 `--ssl-version-max=tls1.2`
없이는 페이지에 닿지도 못했습니다.

## 1. 실패 원인 — 자격증명 거부 (주 원인)

로그인 폼을 그대로(브라우저 없이 `curl` 로도) 재현했더니 서버가 세 갈래로 답을
나눕니다. 값은 출력하지 않고 응답만 적습니다.

| 입력 | 서버 alert |
|---|---|
| 제공된 아이디 + 제공된 비밀번호 | `패스워드가 틀립니다.` |
| 제공된 아이디 + 아무 잘못된 비밀번호 | `관리자 비번 확인` |
| 없는 아이디 | `관리자 아이디 확인` |

- **아이디는 유효**합니다 (없는 아이디였다면 `관리자 아이디 확인` 이 떴을 것).
- 제공된 비밀번호는 거부되지만, 무작위 오답(`관리자 비번 확인`)과 **다른 분기**
  (`패스워드가 틀립니다.`)로 떨어집니다. 즉 서버 인증 로직 안에서 이 비밀번호가
  어떤 검사는 통과하고 다른 검사(관리자 승격/2차 비번으로 추정)에서 걸립니다.
  어느 쪽이든 결과는 "비밀번호 거부" 이고, 이는 **드라이버가 고칠 수 있는 문제가
  아니라 환경변수 `BOARD_PASSWORD_ZEROCLINIC1` 값 자체의 문제**입니다.
- 로그인 JS(`/admin/script/common.js`, 폼의 `fnlogin()`)에는 md5/sha/암호화 등
  **클라이언트 측 비밀번호 변환이 전혀 없습니다.** 폼은 원문 그대로 POST 합니다.
  그래서 `curl` 로 원문을 보낸 결과 == Playwright 드라이버가 채워 보낸 결과입니다.
  드라이버가 값을 잘못 다뤄서 실패한 게 아닙니다.

**팀 조치**: `BOARD_PASSWORD_ZEROCLINIC1` 값을 최신 관리자 비밀번호로 갱신해야
합니다. (혹은 이 계정이 `emp_check`=직원 로그인만 되고 관리자 권한이 없다면 관리자
권한이 있는 계정으로 교체.)

## 2. 실패 원인 — 실행 환경의 TLS 프록시 (부차 원인, 코드 아님)

이 원격 세션의 이그레스 프록시는 Chromium 이 기본(TLS 1.3) 으로 접속하면
`ERR_CONNECTION_RESET` 로 끊습니다. `curl` 은 TLS 1.2 로 자동 낙착되어 200 을
받지만, Chromium 은 낙착하지 않아 `www.zeroclinic1.com` 에 **아예 닿지 못했습니다.**
`--ssl-version-max=tls1.2` 로 브라우저를 띄우자 비로소 로그인 페이지가 떴습니다.

- 이번 정찰에서는 `CHROMIUM_PATH` 로 `--ssl-version-max=tls1.2` 를 붙인 래퍼 스크립트를
  물려 우회했습니다. `src/notionwp/board.py` 의 `chromium.launch(...)` 에는 `args` 가
  없어 이 플래그를 넣을 길이 없습니다 — **이 환경에서 실제 발행을 돌리려면 launch 에
  args 를 넣는 손질이 필요**하지만, 이는 사이트가 아니라 실행 환경 특성입니다.
  (요청대로 코드는 고치지 않았습니다.)
- 또 이 프록시는 `code.jquery.com` 을 403 으로 막습니다. 로그인 페이지는 jQuery 를
  `//code.jquery.com/...` 에서 불러오므로, 정찰 때는 라우팅으로 로컬 jQuery(3.7.1)를
  주입해 대체했습니다. 실 서비스 환경이 이 CDN 을 허용한다면 문제 없습니다.

## 3. 실제로 확인한 로그인 폼 동작

로그인 화면 `https://www.zeroclinic1.com/admin/Login.php` (대문자 L, 프로파일과 일치):

- `<form name="Login" method="post" action="/admin/LoginPost.php" onsubmit="return fnlogin();">`
- 아이디 칸: `<input type="text" id="loginid" name="id">`
- 비밀번호 칸: `<input type="password" id="loginpw" name="Pwd">`
- 숨은 필드: `mode=emp_check`, `frompage=`(빈 값)
- 로그인 버튼은 `<button>`/`submit` 이 **아니라** `<a href="javascript:fnlogin();">` 안에
  `로그인` 글자를 담은 `<div>` 입니다.
- **엔터/버튼 둘 다 동작**: 두 입력칸에 `onkeydown` 으로 Enter(keyCode 13) → `fnlogin()`,
  그리고 `<a>` 클릭 → `fnlogin()`. `fnlogin()` 은 빈 값만 검사한 뒤 `document.Login.submit()`.
- 드라이버는 password 칸에 Enter 를 눌러 제출하고, 실패 시 `a:has-text('로그인')` 을
  클릭하는 폴백을 가집니다. **둘 다 이 폼과 호환됩니다.** 셀렉터 문제 아님.

로그인을 못 넘어서 **로그인 뒤 화면(탭·글쓰기 버튼·에디터·글 링크)은 검증 불가**

# 2차 정찰 (2026-09-09)

요청대로 `CHROMIUM_PATH` 래퍼도 jQuery 주입도 없이, 드라이버 코드 그대로
`inspect()` 를 다시 돌렸습니다. 결과: **1차의 두 환경 문제(TLS·jQuery CDN)는 해소됐고,
로그인은 여전히 서버의 비밀번호 거부에서 막힙니다.** 로그인 뒤 화면(탭·글쓰기 폼·
에디터)에는 이번에도 들어가지 못해, 그 부분은 검증할 수 없었습니다.

## 요약 (한 줄)

TLS 1.2 고정과 `code.jquery.com` 허용이 반영되어 **로그인 페이지는 완전히 정상
렌더**되고 페이지의 jQuery(`fnlogin`)까지 실제로 동작합니다. 그런데 서버가
`BOARD_PASSWORD_ZEROCLINIC1` 값을 **`패스워드가 틀립니다.`** 로 거부합니다. 이번엔
비밀번호가 잘리지 않았는데도(온전한 7자) 거부되므로, 남은 원인은 **값 자체가 현재
관리자 비밀번호와 맞지 않는 것**입니다. 화면·코드로 고칠 수 있는 문제가 아닙니다.

## 1. 환경 문제 두 가지는 해소됨 (더 이상 우회 불필요)

- **TLS**: `board.py` 의 `chromium_args()` 가 프록시 뒤에서 `--ssl-version-max=tls1.2`
  를 자동으로 붙입니다. 그 덕에 별도 래퍼 없이 `www.zeroclinic1.com` 로그인
  페이지가 정상으로 떴습니다. 1차의 `CHROMIUM_PATH` 래퍼는 이제 필요 없습니다.
- **jQuery CDN**: 로그인 페이지는 `//code.jquery.com/jquery-latest.min.js` 와
  `https://code.jquery.com/ui/1.13.2/jquery-ui.js` 를 불러옵니다. 이번엔 로컬 주입
  없이도 페이지의 `fnlogin()`(=`$('#loginpw').val()` 을 쓰는 jQuery 코드)이 실제로
  실행되어 `비밀번호를 입력하세요.` alert 를 띄웠습니다 → `code.jquery.com` 이 이제
  허용되어 jQuery 가 정상 로드됨을 확인. 1차의 jQuery 주입 라우팅도 필요 없습니다.

## 2. 남은 유일한 블로커 — 서버가 비밀번호를 거부

로그인 시도 중 브라우저 알림(서버·클라이언트 혼합) 순서는 다음과 같았습니다.

| 순서 | 알림 문구 | 출처 |
|---|---|---|
| 1 | `패스워드가 틀립니다.` | 서버 `LoginPost.php` (Enter 제출 결과) |
| 2 | `비밀번호를 입력하세요.` | 클라이언트 `fnlogin()` — 재시도 시 폼이 새로 로드되어 pw 칸이 비어 걸림(정상 폴백) |
| 3 | `패스워드가 틀립니다.` | 서버 `LoginPost.php` (폼 직접 제출 폴백 결과) |

- 결정적 신호는 **서버가 두 번 다 `패스워드가 틀립니다.`** 를 돌려준 것입니다.
  1차 기록대로 이 문구는 "존재하지 않는 아이디"(`관리자 아이디 확인`)나 완전 무작위
  오답(`관리자 비번 확인`)과는 **다른 분기**로, 아이디는 유효한데 비밀번호 검사에서
  떨어질 때 나옵니다.
- 값 형태 점검(값은 출력하지 않음): 파싱된 비밀번호는 **7자, 대문자·숫자·기호 혼합,
  앞뒤 따옴표·공백·개행 없음**. 1차의 "잘림" 증상은 사라졌습니다. 즉 드라이버가 값을
  잘못 다루는 문제가 아니라, **값이 현재 관리자 비밀번호와 일치하지 않습니다.**
- 로그인 실패 스크린샷(`20260909-011010-login-failed.png`)에는 **캡차·계정잠금·차단
  배너가 없습니다.** 그냥 로그인 폼으로 되돌아오고 pw 칸만 비워집니다. IP 차단이나
  잠금 정황은 관측되지 않았습니다.
- 로그인 폼 구조는 1차와 동일하며 셀렉터·드라이버 로직과 모두 맞습니다
  (`action=/admin/LoginPost.php`, `name=id`/`name=Pwd`, 숨은 `mode=emp_check`,
  `frompage=`, 클라이언트 해시 없음, `로그인` = `a href=javascript:fnlogin()`).

**팀 조치(1차와 동일, 여전히 유효)**: `BOARD_PASSWORD_ZEROCLINIC1` 을 현재 관리자
비밀번호로 갱신해야 합니다. `mode=emp_check`(직원 로그인) 계정이라 관리자 권한이
없을 가능성도 남아 있으니, 안 되면 관리자 권한 계정으로 교체가 필요합니다.

## 4. 검증 불가로 남은 항목 (비밀번호 갱신 후 재정찰 필요)

로그인을 못 넘어 아래는 이번에도 **전부 미검증**입니다. 프로파일
(`boards/www.zeroclinic1.com.json`)의 해당 데이터 필드는 근거 없이 바꾸지 않았고,
`note` 만 2차 결과로 갱신했습니다. `inspect.json` 은 `steps: []` 에
`login_error`·`dialogs` 만 담긴 상태입니다.

- 목록 화면: 게시판 탭 글자·현재 탭, `글쓰기` 버튼의 태그·href, 글 제목/`수정` 링크의
  href 형식과 글 번호 파라미터 이름(`id_param`), 검색칸 `name`, 페이지네이션.
- 글쓰기 폼: 각 행 머리글(공지·HTML·조회수·작성일·제목·내용)과 입력칸 `name`/`type`,
  라디오 값·라벨, 폼 `action`, 등록 버튼의 태그(`submit` 인지 `a`/`div` 인지, `onclick`).
- 에디터: 서머노트 여부(`.note-editor`), `window.jQuery.fn.summernote` 존재, 툴바
  `data-event` 목록, 코드 보기 버튼, 이미지 대화상자(`input[type=file]` class·업로드 POST 대상).
- 공개 글 주소(`htm/boardseo_read.php?id={id}`)의 id 가 목록 글 번호와 같은지 실물 대조.

## 5. 드라이버 코드에 대한 관찰 (코드는 고치지 않음)

- 로그인 단계 셀렉터·폴백(Enter → `a:has-text('로그인')` → `form.submit()`)은 이 폼과
  **모두 호환**됩니다. 어긋나는 셀렉터는 없습니다. 실패는 순전히 서버의 비밀번호
  거부 때문이며, 코드가 어긋나서가 아닙니다.
- 로그인 뒤 단계(목록·글쓰기·에디터) 셀렉터는 실제 화면을 못 봐서 **맞는지 판단
  불가**입니다. 비밀번호가 갱신되면 그때 `inspect.json` 의 `form_fields`·`editor`·
  `list_links` 를 실제 값과 대조해 프로파일과 셀렉터를 굳혀야 합니다.
