# 노션 → 워드프레스 자동 발행

노션 콘텐츠 플래너에서 발행 조건을 만족한 원고를 워드프레스에 발행하고,
Rank Math 설정까지 채운 뒤 플래너를 '게재완료'로 되돌려 씁니다.

하루 두 번(09:00 · 20:00 KST) 루틴이 자동으로 돌고, 팀원이 `/wp-publish` 로
직접 실행할 수도 있습니다.

---

## 1. 처음 한 번만 하는 설정

### ① 워드프레스에 브리지 플러그인 올리기

> **왜 필요한가**
> 워드프레스 REST API는 등록되지 않은 커스텀 메타를 **에러 없이 조용히 버립니다.**
> Rank Math는 모든 SEO 값을 커스텀 메타에 저장하기 때문에, 이 파일이 없으면
> 글은 정상적으로 올라가는데 Rank Math 항목만 전부 비어 있게 됩니다.

#### 방법 A — 관리자 화면에서 ZIP 업로드 (권장, FTP 불필요)

```bash
# ZIP 만들기
cd notion-wp-publish/wp-mu-plugin
zip -r notion-publish-bridge.zip notion-publish-bridge/
```

워드프레스 관리자 → **플러그인 → 새로 추가 → 플러그인 업로드** → ZIP 선택 →
**지금 설치하기** → **플러그인 활성화**.

#### 방법 B — mu-plugins 폴더에 직접 넣기

파일 시스템에 접근할 수 있다면 `notion-publish-bridge/notion-publish-bridge.php` 를
**`wp-content/mu-plugins/`** 에 두는 방법도 있습니다. 폴더가 없으면 새로 만드세요.
`mu-plugins` 는 활성화 과정이 없고 실수로 비활성화될 일도 없습니다.

접근 경로는 호스팅에 따라 다릅니다.
- 호스팅사 관리 콘솔의 **파일 관리자**(cPanel 파일 관리자, 카페24·가비아 웹FTP 등)
- **FTP/SFTP 클라이언트** (FileZilla 등) — 호스팅사에서 발급한 FTP 계정 사용
- 서버에 **SSH** 접속이 되면 `scp` 로 바로 복사

두 방법의 동작은 같습니다. 어느 쪽이든 아래 확인이 통과하면 됩니다.

설치 확인:

```bash
curl -u "아이디:응용프로그램비밀번호" \
  https://blog.cleartone.co.kr/wp-json/notion-bridge/v1/ping
```

`{"ok":true, ...}` 가 나오면 성공입니다.

### ② 워드프레스 응용 프로그램 비밀번호 만들기

워드프레스 관리자 → 사용자 → 프로필 → **응용 프로그램 비밀번호** 에서 새로 발급합니다.
(로그인 비밀번호가 아닙니다.) 공백이 포함된 형태로 나오는데 그대로 붙여넣어도 됩니다.

### ③ 노션 통합 연결

1. https://www.notion.so/my-integrations 에서 내부 통합을 만들고 시크릿을 복사합니다.
2. **플래너 데이터베이스에 그 통합을 연결합니다.** (플래너 우측 상단 `...` → 연결 → 통합 선택)
   이 단계를 빠뜨리면 권한 오류가 납니다.

### ④ 환경변수 설정

```
NOTION_TOKEN       노션 내부 통합 시크릿 (secret_... 또는 ntn_...)
WP_USER            워드프레스 사용자명
WP_APP_PASSWORD    위 ②에서 발급한 응용 프로그램 비밀번호
```

Claude Code 루틴에서 돌리는 경우, 세션 환경(Environment)의 환경변수에 넣어두면
루틴이 실행될 때마다 자동으로 읽힙니다.

### ⑤ 플래너에 '발행 오류' 상태 추가 (권장)

`진행 상황` 속성에 **`발행 오류`** 옵션을 추가해 주세요.
발행이 실패한 행을 여기로 옮겨서 눈에 띄게 합니다.
없어도 동작은 하지만, 실패한 행이 계속 '컨펌 진행 중'으로 남아 매번 재시도됩니다.

## 2. 실행

```bash
cd notion-wp-publish

# ① 확인만 — 워드프레스·노션 어느 쪽도 건드리지 않습니다
PYTHONPATH=src python3 -m notionwp --dry-run

# ② 준비 + 임시저장 (4·5장 참고)
PYTHONPATH=src python3 -m notionwp --prepare work/
# (이미지를 보고 plan.json 의 alt 를 채운 뒤)
PYTHONPATH=src python3 -m notionwp --plan work/ --draft

# ③ 실제 발행
PYTHONPATH=src python3 -m notionwp --plan work/
```

**처음이라면 ① → ② → ③ 순서로 가세요.**

고객사 설정은 노션 '고객사 설정표'에서 읽어옵니다. 한 번 실행하면 활성 고객사를 전부
처리하고, `--client 이름` 으로 한 곳만 고를 수 있습니다 (7장 참고).

| | 워드프레스 | 노션 |
|---|---|---|
| `--dry-run` | 건드리지 않음 | 건드리지 않음 |
| `--draft` | 초안 생성 + 이미지 업로드 + Rank Math 기입 (**비공개**) | 건드리지 않음 |
| (없음) | 위 전부 + **공개** | 게재완료 + URL 기록 |

`--draft` 는 실제 발행 경로를 전부 태워보되 공개만 하지 않습니다. 그래서
본문 변환·이미지 배치·Rank Math 설정을 워드프레스 편집 화면에서 눈으로 검수할 수 있습니다.
실행이 끝나면 편집 링크를 출력합니다.

확인이 끝나면 `--draft` 없이 다시 돌리세요. **그 초안이 그대로 공개됩니다**
(새 글이 또 생기지 않습니다). 버리려면 워드프레스에서 초안을 삭제하면 됩니다.

의존성은 `requests` 하나입니다. (`pip install -r requirements.txt`)

## 3. 발행 조건

**아래를 전부 만족해야 발행합니다. 하나라도 빠지면 발행하지 않습니다.**

| 조건 | 확인 대상 |
|---|---|
| 진행 상황이 `컨펌 진행 중` | `진행 상황` 속성 |
| 유형이 `롱폼`·`엔티티`·`숏폼` 중 하나 | `유형` 속성 (설정에서 변경 가능) |
| 제목에 텍스트가 있을 것 | `제목` 속성 |
| 발행 예정일이 기재되어 있고 **오늘 이하**일 것 | `발행 예정일` 속성 |
| 페이지 안에 원고가 있을 것 | 페이지 본문 |
| 썸네일이 있을 것 | `썸네일` 속성 |
| 본문 이미지가 있을 것 | `본문 이미지` 속성 (히어로 유형은 면제 — 아래 참고) |
| 메타타이틀이 있을 것 | `메타타이틀` 속성 |
| 메타디스크립션이 있을 것 | `메타디스크립션` 속성 |
| 슬러그가 있을 것 | `슬러그` 속성 |

조건을 통과하지 못한 행은 건드리지 않고 사유만 로그에 남깁니다.

### 분류 이름이 어긋나면 발행하지 않습니다

플래너의 `카테고리` 값이 워드프레스에 **없는 이름이면 발행을 멈추고 '발행 오류'** 로
넘깁니다. 오류 메시지에 워드프레스에 실제로 있는 분류 목록을 함께 보여주므로,
플래너 옵션을 그 이름으로 고치고 다시 돌리면 됩니다.

예전에는 없는 이름이면 그 이름으로 분류를 새로 만들었습니다. 편의 기능이었지만
오타 하나로 유령 분류가 생기고 그 글만 거기 격리되는데도 발행은 성공으로 보고돼서,
며칠 뒤에나 발견됐습니다. 지금은 사람에게 넘깁니다.

카테고리가 **비어 있으면** 분류 없이 발행합니다(워드프레스 기본 분류로 들어갑니다).
원고 생성 단계에서 맞는 옵션을 못 찾으면 비워 두도록 되어 있어서, 이건 정상 경로입니다.

### 히어로 이미지 (숏폼)

설정의 `render.hero_image_types` 에 적힌 유형은 **썸네일 한 장만 올리면 됩니다.**

```json
"render": { "hero_image_types": ["숏폼"] }
```

이 유형은 썸네일이 대표 이미지가 되는 동시에 **본문 맨 위에도 같은 미디어로 삽입**됩니다.
워드프레스에 파일이 두 번 올라가지 않고, ALT도 `thumbnail_alt` 하나만 쓰면 됩니다.
`본문 이미지` 속성은 비워두면 되고, 발행 조건에서도 제외됩니다.

목록에 없는 유형(롱폼·엔티티)은 아무 영향을 받지 않습니다. 히어로 유형에 본문 이미지를
따로 올리면 그건 그대로 뒤쪽에 배치됩니다.

### 중복 발행 방지

발행할 때 워드프레스 글에 노션 페이지 ID를 각인해 둡니다.
하루 두 번 돌아도, 실패해서 여러 번 재시도해도 같은 원고가 두 번 나가지 않습니다.

발행 순서는 **초안 생성 → 노션 ID 각인 → Rank Math 기입 → 공개** 입니다.
중간에 실패하면 글이 초안 상태로 남아 공개되지 않고, 다음 회차가 그 초안을 찾아
이어서 진행합니다.

## 4. 본문을 어디까지 쓰는가

원고 페이지에는 발행하면 안 되는 부분이 섞여 있습니다. 아래 규칙으로 걸러냅니다.

| 블록 | 처리 |
|---|---|
| 상단 회색 안내 callout | 제외 |
| **`콘텐츠 가이드` 토글** | **제외 — 기획안이므로 발행에 쓰지 않습니다** |
| 🤖 자동 생성 원고 callout | 제외 |
| `메타 디스크립션` 라벨과 그 아래 문단 | 제외 (플래너 속성에 이미 있음) |
| `# H1 제목` | 제외 (워드프레스 글 제목이 대신함) |
| **`## H2` ~ 클로징 CTA** | **← 이 구간만 발행합니다** |
| `📋 작성 메타 정보` | 제외 |
| `🔧 구조화 제안` | 제외하되 **이미지 배치 지침으로 읽습니다** |
| `✅ 셀프 점검 결과` | 제외 |
| `⚠️ 사용자 확인 요청` | 제외 |
| `근거 자료 표 (검수용)` | 제외 |

즉 **H1 다음부터, 첫 번째 검수용 섹션 직전까지**가 본문입니다.

## 5. 이미지는 어디에 들어가고 ALT는 어떻게 정해지는가

- `썸네일` 속성 → 워드프레스 **대표 이미지**
- `본문 이미지` 속성 → 글 전체 H2/H3 구간에 **고르게 나눠서** 삽입

ALT는 **이미지를 실제로 보고** 씁니다. 스크립트는 이미지를 볼 수 없으므로
발행을 세 단계로 나눕니다.

```bash
# 1단계 — 이미지를 내려받고 plan.json 생성 (아무것도 발행하지 않음)
PYTHONPATH=src python3 -m notionwp --prepare work/

# 2단계 — 이미지를 보고 plan.json 의 alt 를 채웁니다
#          (루틴에서는 Claude가, 손으로 할 때는 사람이)

# 3단계 — 검수된 ALT로 발행
PYTHONPATH=src python3 -m notionwp --plan work/ --draft
```

`plan.json` 에는 본문 헤딩 구조와 각 구간의 발췌가 함께 들어갑니다.
같은 장비 사진이라도 어느 섹션에 놓이느냐에 따라 ALT가 달라져야 하기 때문입니다.

```jsonc
{
  "sections": [
    { "anchor": 31, "level": 2, "heading": "삼성역 피부과 선택 기준 4가지…",
      "excerpt": "장비 목록보다 먼저 확인할 것은…" }
  ],
  "images": [
    { "n": 2, "preview": "images/2-preview.jpg", "anchor": 31, "alt": "" }
  ]
}
```

- `alt` 를 채웁니다. 하나라도 비어 있으면 3단계가 거부합니다.
- `anchor` 를 바꾸면 배치를 옮길 수 있습니다 (`sections[].anchor` 값 사용).
- `preview` 는 긴 변 1024px로 줄인 사본입니다. 원본은 `original` 이 가리킵니다.

> `--plan` 없이 그냥 돌리면 예전 방식(원고의 `🔧 구조화 제안 > 이미지 alt 텍스트 가이드`)
> 으로 폴백합니다. 준비 단계를 건너뛰어야 할 때를 위한 안전장치입니다.

**1단계에서 이미지를 이미 받아두므로, 3단계는 노션 첨부 주소(1시간 만료)를
다시 부르지 않습니다.** 2단계에 시간이 걸려도 안전합니다.

**파일명은 슬러그 기반 영문으로 바꿔서 올립니다.**
(`기미레이저횟수1.jpg` → `melasma-laser-sessions-1.jpg`)
한글 파일명은 주소가 깨지고, 이미지 주소도 검색엔진이 읽는 정보이기 때문입니다.

> 노션 첨부 주소는 약 1시간 뒤 만료됩니다. 그래서 링크를 그대로 넘기지 않고
> 매번 내려받아 워드프레스에 다시 올립니다. 팀 가이드에 적힌
> "노션에서 붙여넣으면 이미지가 안 따라온다"는 문제가 여기서 자동으로 해결됩니다.

## 6. Rank Math에 무엇이 들어가는가

내부 가이드 ⑤단계에 해당합니다.

| 가이드 항목 | 자동 처리 | 출처 |
|---|---|---|
| 스니펫 — 타이틀 | `rank_math_title` | 플래너 `메타타이틀` |
| 스니펫 — 설명 | `rank_math_description` | 플래너 `메타디스크립션` |
| 스니펫 — 퍼머링크 | 글 슬러그 | 플래너 `슬러그` |
| 포커스 키워드 | `rank_math_focus_keyword` | 플래너 `키워드` (첫 번째가 메인) |
| 스키마 | `rank_math_schema_*` | 원고에서 자동 생성 |

### 스키마

가이드 기준을 그대로 따릅니다.

- 기본으로 붙는 **Article 스키마는 쓰지 않습니다** (기입 전에 기존 스키마를 비웁니다)
- **BlogPosting** — 항상 생성
- **FAQPage** — 원고에 FAQ 섹션(`### Q1.` 형식)이 있을 때만 생성

Rank Math 스키마 탭에 그대로 보이므로 팀원이 눈으로 확인하고 수정할 수 있습니다.

만약 스키마 탭이 이상하게 보이면 설정에서 `"schema_mode": "jsonld"` 로 바꾸세요.
UI에는 안 보이지만 JSON-LD 출력은 확실하게 나갑니다.

### 점수(초록 배지)에 대해

Rank Math의 0~100 점수는 **에디터 안에서 자바스크립트가 계산해서** 저장합니다.
API로 발행하면 그 코드가 돌지 않아 점수가 찍히지 않습니다.

다만 점수는 내부 지표이지 검색엔진에 나가는 값이 아닙니다.
실제로 구글이 읽는 것은 타이틀·설명·슬러그·스키마·H태그·ALT이고, 그건 전부 위에서 채워집니다.
점수를 확인하고 싶으면 발행된 글을 에디터에서 한 번 열면 그 자리에서 계산됩니다.

## 7. 새 고객사 추가하기

**저장소에서 할 일이 없습니다.** 노션 '고객사 설정표'에 행을 하나 추가하면 끝입니다.

| 컬럼 | 값 | 필수 |
|---|---|---|
| 고객사 | 표시 이름. 브랜드 접미사·작성자 기본값으로도 쓰입니다 | ○ |
| 상태 | `활성` 이어야 처리합니다. `일시중지` 면 건너뜁니다 | ○ |
| 플래너 DB ID | 플래너 URL을 통째로 붙여넣어도 32자리만 뽑아 씁니다 | ○ |
| **워드프레스 주소** | `https://blog.고객사.co.kr`. **비어 있으면 발행 대상에서 빠집니다** | ○ |
| 대상 유형 | `롱폼, 숏폼, 브랜드 엔티티, 제품 엔티티`. 비우면 유형 무관 | |
| 유튜브 채널 | `https://www.youtube.com/@핸들` · `UC…` · 채널 주소. 비우면 영상을 넣지 않습니다 | |

**워드프레스 주소를 비워두면 그 고객사는 원고 생성만 하고 발행은 하지 않습니다.**
의도한 상태일 수도 있어서 오류로 처리하지 않지만, 실행 로그에 사유가 남습니다.

### 카테고리와 플래너 컬럼 이름

**둘 다 이름을 그대로 씁니다.** 중간에 바꿔주는 대응표가 없습니다.

- **카테고리** — 플래너의 `카테고리` 옵션을 **워드프레스에 이미 있는 분류 이름 그대로** 만들어
  두세요. 이름이 어긋나면 발행할 때 워드프레스에 그 이름의 분류가 **새로 만들어집니다.**
  오류가 나지 않으므로, 새 고객사 첫 발행은 `--draft` 로 한 번 확인하는 편이 안전합니다.
  (분류가 새로 생기면 실행 로그에 `카테고리를 새로 만들었습니다` 가 남습니다.)
- **플래너 컬럼** — 전 고객사가 같은 템플릿을 복제해 쓰므로 이름이 늘 같습니다.
  `제목` `진행 상황` `유형` `발행 예정일` `썸네일` `본문 이미지` `메타타이틀`
  `메타디스크립션` `슬러그` `키워드` `카테고리` `게시판` `URL`

예외적으로 이름을 바꿔야 하는 고객사가 생기면 `config/defaults.json` 의
`wordpress.category_map` · `notion.properties` 로 처리할 수 있지만, 그건 전 고객사에
적용되는 공통값이므로 되도록 쓰지 마세요. 이름을 맞추는 쪽이 낫습니다.

### 저장소에 남은 것

`config/defaults.json` 에는 **전 고객사 공통값만** 있습니다. 상태 이름, 플래너 컬럼
이름, 여백·표 정렬 같은 렌더링 설정, 실행 로그 DB, 설정표 위치입니다.
고객사 고유값은 하나도 없습니다.

`--config 파일.json` 으로 표를 거치지 않고 돌릴 수도 있지만, 표에 없는 임시 대상을
확인할 때만 쓰세요. 같은 고객사를 표와 파일 양쪽에 두면 값이 어긋납니다.

### 유튜브 영상 자동 삽입

설정표에 유튜브 채널이 적혀 있으면, 준비 단계가 그 채널의 영상 목록을 `plan.json` 의
`video_candidates` 에 담습니다. 검수 단계에서 원고 주제와 맞는 영상 하나를 골라
`video` 를 채우면, 발행할 때 그 자리에 구텐베르크 embed 블록으로 들어갑니다.
맨 URL 을 문단에 넣으면 링크 한 줄로만 나가므로 embed 블록이어야 썸네일이 뜹니다.

```jsonc
"video": { "url": "https://www.youtube.com/watch?v=...", "anchor": 23, "note": "한 줄 안내" }
```

**맞는 영상이 없으면 비워두는 것이 기본값입니다.** 주제가 어긋나는 영상을 억지로
붙이는 것보다 없는 편이 낫습니다.

목록을 가져오는 경로가 둘입니다.

| | 가져오는 범위 | 필요한 것 |
|---|---|---|
| YouTube Data API | 채널 **전체** | `YOUTUBE_API_KEY` 환경변수 (전 고객사 공통) |
| 채널 RSS (폴백) | **최신 15개** | 채널 ID(`UC…`) — 핸들만으로는 안 됩니다 |

API 조회가 실패하면 자동으로 RSS 로 물러나고, 그것도 실패하면 후보를 비운 채
발행을 계속합니다. **영상 때문에 발행이 막히지는 않습니다.**

허용 도메인에 `*.youtube.com` 과 `*.googleapis.com` 이 필요합니다.

### 고객사마다 다른 워드프레스 계정

고객사의 워드프레스는 서로 다른 설치본이라 계정도 다릅니다. 주소에서 뽑은 키로
그 고객사 전용 환경변수를 먼저 찾고, 없으면 공용 값으로 물러납니다.

```
blog.cleartone.co.kr  →  WP_USER_CLEARTONE / WP_APP_PASSWORD_CLEARTONE
example.com           →  WP_USER_EXAMPLE  / WP_APP_PASSWORD_EXAMPLE
        (없으면)      →  WP_USER          / WP_APP_PASSWORD
```

설정표에 컬럼을 더 두지 않고 주소에서 키를 만들기 때문에, 새 고객사는 **환경변수
두 줄만** 추가하면 됩니다. 고객사가 한 곳뿐이면 지금처럼 공용 값만 써도 됩니다.

계정을 못 찾으면 발행 전에 멈추고 **어떤 이름으로 넣어야 하는지 알려줍니다.**
아이디만 넣고 비밀번호를 빠뜨린 경우도 막습니다 — 반쪽만 있으면 아이디는 전용,
비밀번호는 공용이 섞여 엉뚱한 계정으로 로그인하게 됩니다.

## 8. 실행 로그

`run_log.database_id` 가 있으면 발행을 돌릴 때마다 노션 '자동화 실행 로그' DB에
한 줄을 남깁니다. 1단계(원고 생성) 루틴이 쓰는 것과 같은 DB이고, `단계` 열로
어느 쪽이 남긴 기록인지 구분합니다.

| 열 | 값 |
| --- | --- |
| 실행 | `2026-08-13 20:05 고객사 · 워드프레스 발행` |
| 단계 | 워드프레스 발행 |
| 결과 | 성공 · 부분 성공 · 실패 · 대상 없음 |
| 처리 건수 | 실제로 공개된 글 수 |
| 상세 | 발행한 글과 주소, 실패 사유, 발행 직전에 걸린 행과 이유 |

- 기록하는 회차: `--plan` / 인자 없는 실제 발행. `--prepare` 는 대상이 0건일 때만
  남깁니다(뒤이어 `--plan` 이 돌지 않아 그날 기록이 통째로 비기 때문입니다).
- 기록하지 않는 회차: `--dry-run`, `--draft`. 둘 다 공개하지 않고 노션도 건드리지
  않으므로 운영 기록으로 남길 것이 없습니다.
- 로그 쓰기가 실패해도 발행은 그대로 유효합니다. 경고만 남기고 넘어갑니다.

`아직 작성 중`처럼 매일 걸리는 행은 상세에 넣지 않습니다. 발행 직전까지 갔다가
이미지·메타 같은 것이 비어서 걸린 행만 남겨야 로그를 열었을 때 할 일이 보입니다.

로그 DB는 플래너와 별개이므로, **그 DB에도 노션 통합을 연결**해야 합니다
(DB 우측 상단 ⋯ → 연결). 연결이 없으면 발행은 되고 로그만 조용히 실패합니다.

## 9. 마스터 시트에 발행 로그 기입

> **더 간단한 길이 있습니다.** 같은 일을 구글 Apps Script로도 할 수 있고, 그쪽은
> 서비스 계정·환경변수 없이 구글 계정 하나로 5분이면 끝납니다.
> `apps-script/README.md` 를 보세요. **둘 중 하나만 쓰면 됩니다.**
> 아래는 Claude Code 루틴에서 돌리고 싶을 때의 경로입니다.

고객사와 함께 보는 구글 스프레드시트의 **`7) 발행 로그`** 탭에, 플래너에서 발행이
끝난 글을 한 줄씩 옮겨 적습니다. 워드프레스 발행과는 별개로 도는 독립 명령이라,
워드프레스가 아닌 곳(자체 게시판·네이버 등)에 올린 글도 URL만 플래너에 적혀 있으면
똑같이 기록됩니다.

```bash
PYTHONPATH=src python3 -m notionwp.sheetsync --dry-run   # 무엇이 들어갈지만 확인
PYTHONPATH=src python3 -m notionwp.sheetsync             # 실제 기입
PYTHONPATH=src python3 -m notionwp.sheetsync --client 제로클리닉
```

### 무엇을 옮기는가

| 마스터 시트 | 노션 플래너 |
| --- | --- |
| 날짜 | 발행 예정일 |
| 콘텐츠 유형 | 유형 |
| 제목 | 제목 |
| 게재본 | URL |

**URL이 채워진 행**을 발행이 끝난 것으로 봅니다. 진행 상황은 기본적으로 보지
않습니다 — 플래너마다 상태 이름이 다르고(`발행완료` · `게재완료`), URL이 적혔다는
것 자체가 게재됐다는 뜻이기 때문입니다. 상태까지 확인하려면 설정에
`"status_done": ["발행완료"]` 를 넣으세요.

URL은 있는데 제목·유형·날짜 중 하나가 비어 있으면 기입하지 않고 실행 결과에
남깁니다. 사람이 플래너를 채워야 하는 상황입니다.

### 시트를 어떻게 건드리는가

- **덧쓰지 않습니다.** 제목과 게재본이 둘 다 빈 줄에만 씁니다. 유형만 미리 적어둔
  예정 줄이 있으면 그 줄부터 채우고, 다 차면 표 아래로 이어 붙입니다.
- **몇 번을 돌려도 같습니다.** 게재본 주소로 이미 적힌 것을 걸러내므로 같은 글이
  두 줄로 늘어나지 않습니다. 하루 두 번 도는 루틴에 그대로 붙여도 됩니다.
- 헤더는 `날짜 · 콘텐츠 유형 · 제목 · 게재본` 이 한 줄에 모두 있는 줄을 위에서부터
  찾습니다. 표가 몇 번째 줄에서 시작하든 상관없습니다.

### 처음 한 번만 하는 설정

#### ① 구글 서비스 계정 만들기

사람 계정을 쓰면 담당자가 바뀔 때 자동화가 멈추고, 고객사 시트에 토큰을 심으면
고객사 쪽에서 그 토큰이 보입니다. 그래서 자동화 전용 계정을 하나 씁니다.

1. https://console.cloud.google.com 에서 프로젝트를 하나 만듭니다(있으면 그대로).
2. **API 및 서비스 → 라이브러리 → Google Sheets API → 사용** 을 누릅니다.
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정**.
4. 만들어진 서비스 계정 → **키 → 키 추가 → 새 키 만들기 → JSON**. 파일이 내려받아집니다.
5. 그 계정의 이메일 주소(`...@....iam.gserviceaccount.com`)를 복사해 둡니다.

#### ② 마스터 시트를 그 계정에 공유

스프레드시트 우측 상단 **공유** → 위에서 복사한 서비스 계정 이메일을 **편집자**로
추가합니다. 이 단계를 빠뜨리면 403이 납니다(오류 메시지에 어느 주소로 공유해야
하는지 그대로 나옵니다).

#### ③ 플래너에 노션 통합 연결

플래너 DB 우측 상단 `⋯` → **연결** → 워드프레스 자동화에 쓰는 통합을 고릅니다.
1장 ③과 같은 통합을 그대로 쓰면 됩니다.

#### ④ 환경변수

```
GOOGLE_SERVICE_ACCOUNT_JSON   ①에서 받은 JSON 파일의 경로, 또는 그 내용 자체
```

`NOTION_TOKEN` 은 워드프레스 발행과 같은 값을 씁니다.

#### ⑤ 대상 등록

`config/sheet-log.json` 의 `targets` 에 고객사를 한 줄 추가합니다.

```jsonc
{
  "client": "제로클리닉",
  "planner_db": "37b68fa2-06ff-80c5-a520-e7500fac7d0e",  // 주소를 통째로 붙여넣어도 됩니다
  "spreadsheet": "1fGmSvJzA9y46KQTuKEnuSlknwPkcJcDOtzUq9Fe1Sek",  // 주소의 /d/ 와 /edit 사이
  "sheet": "7) 발행 로그",
  "properties": { "date": "발행 예정일", "type": "유형", "title": "제목", "url": "URL" }
}
```

`properties` 와 `columns` 는 이름이 기본값과 같으면 생략해도 됩니다.
고객사 설정표(노션)를 쓰지 않는 이유는, 이 기능이 워드프레스 발행 대상이 아닌
고객사에도 붙기 때문입니다. 설정표에 넣으면 원고 생성 루틴까지 그 고객사를
집어가게 됩니다.

### 실행 로그

실제로 기입한 회차는 노션 '자동화 실행 로그' DB에 `단계 = 마스터 시트 기록` 으로
한 줄 남습니다. `--dry-run` 은 남기지 않습니다.
