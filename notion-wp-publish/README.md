# 노션 → 워드프레스 자동 발행

노션 콘텐츠 플래너에서 발행 조건을 만족한 원고를 워드프레스에 발행하고,
Rank Math 설정까지 채운 뒤 플래너를 '게재완료'로 되돌려 씁니다.

하루 두 번(09:00 · 20:00 KST) 루틴이 자동으로 돌고, 팀원이 `/wp-publish` 로
직접 실행할 수도 있습니다.

---

## 1. 처음 한 번만 하는 설정

### ① 워드프레스에 브리지 플러그인 올리기

> **왜 필요한가**
> 워드프레스 REST API는 등록되지 않은 커스텀 메타를 **에러 없이 조용히 버립니다.**
> Rank Math는 모든 SEO 값을 커스텀 메타에 저장하기 때문에, 이 파일이 없으면
> 글은 정상적으로 올라가는데 Rank Math 항목만 전부 비어 있게 됩니다.

#### 방법 A — 관리자 화면에서 ZIP 업로드 (권장, FTP 불필요)

```bash
# ZIP 만들기
cd notion-wp-publish/wp-mu-plugin
zip -r notion-publish-bridge.zip notion-publish-bridge/
```

워드프레스 관리자 → **플러그인 → 새로 추가 → 플러그인 업로드** → ZIP 선택 →
**지금 설치하기** → **플러그인 활성화**.

#### 방법 B — mu-plugins 폴더에 직접 넣기

파일 시스템에 접근할 수 있다면 `notion-publish-bridge/notion-publish-bridge.php` 를
**`wp-content/mu-plugins/`** 에 두는 방법도 있습니다. 폴더가 없으면 새로 만드세요.
`mu-plugins` 는 활성화 과정이 없고 실수로 비활성화될 일도 없습니다.

접근 경로는 호스팅에 따라 다릅니다.
- 호스팅사 관리 콘솔의 **파일 관리자**(cPanel 파일 관리자, 카페24·가비아 웹FTP 등)
- **FTP/SFTP 클라이언트** (FileZilla 등) — 호스팅사에서 발급한 FTP 계정 사용
- 서버에 **SSH** 접속이 되면 `scp` 로 바로 복사

두 방법의 동작은 같습니다. 어느 쪽이든 아래 확인이 통과하면 됩니다.

설치 확인:

```bash
curl -u "아이디:응용프로그램비밀번호" \
  https://blog.cleartone.co.kr/wp-json/notion-bridge/v1/ping
```

`{"ok":true, ...}` 가 나오면 성공입니다.

### ② 워드프레스 응용 프로그램 비밀번호 만들기

워드프레스 관리자 → 사용자 → 프로필 → **응용 프로그램 비밀번호** 에서 새로 발급합니다.
(로그인 비밀번호가 아닙니다.) 공백이 포함된 형태로 나오는데 그대로 붙여넣어도 됩니다.

### ③ 노션 통합 연결

1. https://www.notion.so/my-integrations 에서 내부 통합을 만들고 시크릿을 복사합니다.
2. **플래너 데이터베이스에 그 통합을 연결합니다.** (플래너 우측 상단 `...` → 연결 → 통합 선택)
   이 단계를 빠뜨리면 권한 오류가 납니다.

### ④ 환경변수 설정

```
NOTION_TOKEN       노션 내부 통합 시크릿 (secret_... 또는 ntn_...)
WP_USER            워드프레스 사용자명
WP_APP_PASSWORD    위 ②에서 발급한 응용 프로그램 비밀번호
```

Claude Code 루틴에서 돌리는 경우, 세션 환경(Environment)의 환경변수에 넣어두면
루틴이 실행될 때마다 자동으로 읽힙니다.

### ⑤ 플래너에 '발행 오류' 상태 추가 (권장)

`진행 상황` 속성에 **`발행 오류`** 옵션을 추가해 주세요.
발행이 실패한 행을 여기로 옮겨서 눈에 띄게 합니다.
없어도 동작은 하지만, 실패한 행이 계속 '컨펌 진행 중'으로 남아 매번 재시도됩니다.

## 2. 실행

```bash
cd notion-wp-publish

# ① 확인만 — 워드프레스·노션 어느 쪽도 건드리지 않습니다
PYTHONPATH=src python3 -m notionwp --config config/cleartone.json --dry-run

# ② 준비 + 임시저장 (4·5장 참고)
PYTHONPATH=src python3 -m notionwp --config config/cleartone.json --prepare work/
# (이미지를 보고 plan.json 의 alt 를 채운 뒤)
PYTHONPATH=src python3 -m notionwp --config config/cleartone.json --plan work/ --draft

# ③ 실제 발행
PYTHONPATH=src python3 -m notionwp --config config/cleartone.json --plan work/
```

**처음이라면 ① → ② → ③ 순서로 가세요.**

| | 워드프레스 | 노션 |
|---|---|---|
| `--dry-run` | 건드리지 않음 | 건드리지 않음 |
| `--draft` | 초안 생성 + 이미지 업로드 + Rank Math 기입 (**비공개**) | 건드리지 않음 |
| (없음) | 위 전부 + **공개** | 게재완료 + URL 기록 |

`--draft` 는 실제 발행 경로를 전부 태워보되 공개만 하지 않습니다. 그래서
본문 변환·이미지 배치·Rank Math 설정을 워드프레스 편집 화면에서 눈으로 검수할 수 있습니다.
실행이 끝나면 편집 링크를 출력합니다.

확인이 끝나면 `--draft` 없이 다시 돌리세요. **그 초안이 그대로 공개됩니다**
(새 글이 또 생기지 않습니다). 버리려면 워드프레스에서 초안을 삭제하면 됩니다.

의존성은 `requests` 하나입니다. (`pip install -r requirements.txt`)

## 3. 발행 조건

**아래를 전부 만족해야 발행합니다. 하나라도 빠지면 발행하지 않습니다.**

| 조건 | 확인 대상 |
|---|---|
| 진행 상황이 `컨펌 진행 중` | `진행 상황` 속성 |
| 유형이 `롱폼`·`엔티티`·`숏폼` 중 하나 | `유형` 속성 (설정에서 변경 가능) |
| 제목에 텍스트가 있을 것 | `제목` 속성 |
| 발행 예정일이 기재되어 있고 **오늘 이하**일 것 | `발행 예정일` 속성 |
| 페이지 안에 원고가 있을 것 | 페이지 본문 |
| 썸네일이 있을 것 | `썸네일` 속성 |
| 본문 이미지가 있을 것 | `본문 이미지` 속성 |
| 메타타이틀이 있을 것 | `메타타이틀` 속성 |
| 메타디스크립션이 있을 것 | `메타디스크립션` 속성 |
| 슬러그가 있을 것 | `슬러그` 속성 |

조건을 통과하지 못한 행은 건드리지 않고 사유만 로그에 남깁니다.

### 중복 발행 방지

발행할 때 워드프레스 글에 노션 페이지 ID를 각인해 둡니다.
하루 두 번 돌아도, 실패해서 여러 번 재시도해도 같은 원고가 두 번 나가지 않습니다.

발행 순서는 **초안 생성 → 노션 ID 각인 → Rank Math 기입 → 공개** 입니다.
중간에 실패하면 글이 초안 상태로 남아 공개되지 않고, 다음 회차가 그 초안을 찾아
이어서 진행합니다.

## 4. 본문을 어디까지 쓰는가

원고 페이지에는 발행하면 안 되는 부분이 섞여 있습니다. 아래 규칙으로 걸러냅니다.

| 블록 | 처리 |
|---|---|
| 상단 회색 안내 callout | 제외 |
| **`콘텐츠 가이드` 토글** | **제외 — 기획안이므로 발행에 쓰지 않습니다** |
| 🤖 자동 생성 원고 callout | 제외 |
| `메타 디스크립션` 라벨과 그 아래 문단 | 제외 (플래너 속성에 이미 있음) |
| `# H1 제목` | 제외 (워드프레스 글 제목이 대신함) |
| **`## H2` ~ 클로징 CTA** | **← 이 구간만 발행합니다** |
| `📋 작성 메타 정보` | 제외 |
| `🔧 구조화 제안` | 제외하되 **이미지 배치 지침으로 읽습니다** |
| `✅ 셀프 점검 결과` | 제외 |
| `⚠️ 사용자 확인 요청` | 제외 |
| `근거 자료 표 (검수용)` | 제외 |

즉 **H1 다음부터, 첫 번째 검수용 섹션 직전까지**가 본문입니다.

## 5. 이미지는 어디에 들어가고 ALT는 어떻게 정해지는가

- `썸네일` 속성 → 워드프레스 **대표 이미지**
- `본문 이미지` 속성 → 글 전체 H2/H3 구간에 **고르게 나눠서** 삽입

ALT는 **이미지를 실제로 보고** 씁니다. 스크립트는 이미지를 볼 수 없으므로
발행을 세 단계로 나눕니다.

```bash
# 1단계 — 이미지를 내려받고 plan.json 생성 (아무것도 발행하지 않음)
PYTHONPATH=src python3 -m notionwp --config config/cleartone.json --prepare work/

# 2단계 — 이미지를 보고 plan.json 의 alt 를 채웁니다
#          (루틴에서는 Claude가, 손으로 할 때는 사람이)

# 3단계 — 검수된 ALT로 발행
PYTHONPATH=src python3 -m notionwp --config config/cleartone.json --plan work/ --draft
```

`plan.json` 에는 본문 헤딩 구조와 각 구간의 발췌가 함께 들어갑니다.
같은 장비 사진이라도 어느 섹션에 놓이느냐에 따라 ALT가 달라져야 하기 때문입니다.

```jsonc
{
  "sections": [
    { "anchor": 31, "level": 2, "heading": "삼성역 피부과 선택 기준 4가지…",
      "excerpt": "장비 목록보다 먼저 확인할 것은…" }
  ],
  "images": [
    { "n": 2, "preview": "images/2-preview.jpg", "anchor": 31, "alt": "" }
  ]
}
```

- `alt` 를 채웁니다. 하나라도 비어 있으면 3단계가 거부합니다.
- `anchor` 를 바꾸면 배치를 옮길 수 있습니다 (`sections[].anchor` 값 사용).
- `preview` 는 긴 변 1024px로 줄인 사본입니다. 원본은 `original` 이 가리킵니다.

> `--plan` 없이 그냥 돌리면 예전 방식(원고의 `🔧 구조화 제안 > 이미지 alt 텍스트 가이드`)
> 으로 폴백합니다. 준비 단계를 건너뛰어야 할 때를 위한 안전장치입니다.

**1단계에서 이미지를 이미 받아두므로, 3단계는 노션 첨부 주소(1시간 만료)를
다시 부르지 않습니다.** 2단계에 시간이 걸려도 안전합니다.

**파일명은 슬러그 기반 영문으로 바꿔서 올립니다.**
(`기미레이저횟수1.jpg` → `melasma-laser-sessions-1.jpg`)
한글 파일명은 주소가 깨지고, 이미지 주소도 검색엔진이 읽는 정보이기 때문입니다.

> 노션 첨부 주소는 약 1시간 뒤 만료됩니다. 그래서 링크를 그대로 넘기지 않고
> 매번 내려받아 워드프레스에 다시 올립니다. 팀 가이드에 적힌
> "노션에서 붙여넣으면 이미지가 안 따라온다"는 문제가 여기서 자동으로 해결됩니다.

## 6. Rank Math에 무엇이 들어가는가

내부 가이드 ⑤단계에 해당합니다.

| 가이드 항목 | 자동 처리 | 출처 |
|---|---|---|
| 스니펫 — 타이틀 | `rank_math_title` | 플래너 `메타타이틀` |
| 스니펫 — 설명 | `rank_math_description` | 플래너 `메타디스크립션` |
| 스니펫 — 퍼머링크 | 글 슬러그 | 플래너 `슬러그` |
| 포커스 키워드 | `rank_math_focus_keyword` | 플래너 `키워드` (첫 번째가 메인) |
| 스키마 | `rank_math_schema_*` | 원고에서 자동 생성 |

### 스키마

가이드 기준을 그대로 따릅니다.

- 기본으로 붙는 **Article 스키마는 쓰지 않습니다** (기입 전에 기존 스키마를 비웁니다)
- **BlogPosting** — 항상 생성
- **FAQPage** — 원고에 FAQ 섹션(`### Q1.` 형식)이 있을 때만 생성

Rank Math 스키마 탭에 그대로 보이므로 팀원이 눈으로 확인하고 수정할 수 있습니다.

만약 스키마 탭이 이상하게 보이면 설정에서 `"schema_mode": "jsonld"` 로 바꾸세요.
UI에는 안 보이지만 JSON-LD 출력은 확실하게 나갑니다.

### 점수(초록 배지)에 대해

Rank Math의 0~100 점수는 **에디터 안에서 자바스크립트가 계산해서** 저장합니다.
API로 발행하면 그 코드가 돌지 않아 점수가 찍히지 않습니다.

다만 점수는 내부 지표이지 검색엔진에 나가는 값이 아닙니다.
실제로 구글이 읽는 것은 타이틀·설명·슬러그·스키마·H태그·ALT이고, 그건 전부 위에서 채워집니다.
점수를 확인하고 싶으면 발행된 글을 에디터에서 한 번 열면 그 자리에서 계산됩니다.

## 7. 새 고객사 추가하기

`config/cleartone.json` 을 복사해서 값만 바꾸면 됩니다.

```jsonc
{
  "client": "고객사 이름",
  "notion": {
    "database_id": "플래너 데이터베이스 ID",
    "status_ready": "컨펌 진행 중",   // 이 상태일 때만 발행
    "status_done":  "게재완료",       // 발행 후 이 상태로 변경
    "status_error": "발행 오류",
    "type_filter": ["롱폼", "엔티티", "숏폼"], // 빈 배열이면 유형 무관
    "properties": { /* 플래너 컬럼 이름 그대로 */ }
  },
  "wordpress": {
    "base_url": "https://고객사도메인",
    "category_map": { "노션 카테고리": "워드프레스 카테고리" }
  }
}
```

`properties` 는 **플래너의 실제 컬럼 이름**과 정확히 같아야 합니다.
고객사마다 컬럼 이름이 조금씩 다르므로 여기서 흡수합니다.

워드프레스에 없는 카테고리는 자동으로 만들어집니다.
