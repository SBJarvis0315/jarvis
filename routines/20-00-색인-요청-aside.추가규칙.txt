## 이미 색인 요청된 행은 다시 요청하지 않고 '완료'로만 바꾼다

팀원이 서치콘솔에서 직접 색인 요청을 해 두고 플래너 값은 '대기'로 남겨두는
경우가 있다. 같은 URL을 한 번 더 요청해 그날 할당량만 쓰는 일을 막기 위해,
아래 두 경우를 '이미 요청된 건'으로 보고 처리한다.

(가) URL 검사 결과 화면에 색인 생성 요청 기록이 이미 보인다.
     예: '색인 생성을 이미 요청했습니다', '색인 생성 요청이 N일 전에 전송됨',
     이 URL이 이미 우선순위 크롤링 대기열에 있다는 안내.
     → 색인 생성 요청 버튼을 누르지 않는다.

(나) 색인 생성 요청을 눌렀더니 구글이 새 접수가 아니라
     '이미 요청했습니다 · 이미 우선순위 크롤링 대기열에 있습니다' 류로 답한다.
     → 재시도하지 않는다.

두 경우 모두 그 행은 아래와 같이만 처리한다.

- '색인 요청' 값을 '대기'에서 '완료'로 바꾼다. 이것만 한다.
- 스크린샷을 저장하지 않는다.
- 플래너에 댓글을 달지 않는다.
- 실행 요약에 별도 항목을 만들지 않는다. 집계는 '완료'에 함께 넣는다.

지켜야 할 선:

- '대기'인 행만 대상이다. '완료'·'오류'·'개수 제한'·빈 값은 지금까지와 같이
  보지 않고 건드리지 않는다.
- 검사 결과가 'URL이 Google에 등록되어 있음'이라는 것만으로는 건너뛰지 않는다.
  글을 고친 뒤 재색인을 받으려고 팀원이 '완료'를 '대기'로 되돌려 둔 행이
  그렇게 보이기 때문이다. 요청 기록이 따로 보이지 않으면 지금까지처럼 요청한다.
- 화면이 애매해서 이미 요청된 건인지 확신이 안 서면, 요청된 것으로 단정하지 말고
  지금까지처럼 색인 생성 요청을 누른다. 한 번 더 요청하는 쪽이 빠뜨리는 쪽보다 낫다.
- 이 규칙은 '대기 → 완료' 한 방향만 허용한다. 어떤 경우에도 '완료'를 '대기'로
  되돌리거나 '오류'·'개수 제한'으로 바꾸지 않는다.
