# 주간 회의록 자동 복제

매주 월요일 사람이 손으로 하던 일을 그대로 합니다: 지난주 회의록 페이지를
복제하고, 복제본 제목 뒤에 붙는 ` (1)` 을 지우고, WEEK 번호를 하나 올리고,
날짜를 이번 주 월요일로 바꿉니다. 본문은 **손대지 않습니다** — 지난주 표·체크리스트가
그대로 넘어와야 팀이 그 위에 이번 주 내용을 덮어 씁니다.

## 고정 정보

| 항목 | 값 |
|---|---|
| 상위 페이지 | 주간 회의 & 투두 — https://app.notion.com/p/29168fa206ff80efa266c79dd50a23f7 |
| 회의록 DB (data source) | `collection://29168fa2-06ff-812e-99b6-000b29b4cea3` |
| 속성 | `주`(제목) · `날짜`(date) · `참석자`(person) |
| 시간대 | Asia/Seoul |

모든 노션 작업은 Notion MCP 커넥터 도구로 합니다. 도구가 안 보이면 ToolSearch 로
`notion-query-data-sources`, `notion-duplicate-page`, `notion-update-page` 를 로드하세요.
Notion 도구가 아예 없으면 그 사실만 보고하고 끝냅니다. 다른 경로로 우회하지 않습니다.

## 절차

### 1. 오늘 날짜와 이번 주 월요일을 정한다

Asia/Seoul 기준 오늘이 월요일이면 오늘이 기준일입니다. 월요일이 아니면(사람이
화요일에 직접 실행한 경우 등) **이번 주 월요일**을 기준일로 씁니다.

```bash
TZ=Asia/Seoul python3 -c "import datetime as d; t=d.date.today(); print(t - d.timedelta(days=t.weekday()))"
```

### 2. 최근 페이지를 한 번만 조회한다

SQL 로 날짜 내림차순 상위 3개만 가져옵니다. 전체 페이지를 fetch 하지 마세요 —
회의록 본문은 매우 길어서 열 필요가 없습니다.

```sql
SELECT url, "주", "date:날짜:start"
FROM "collection://29168fa2-06ff-812e-99b6-000b29b4cea3"
WHERE "date:날짜:start" IS NOT NULL
ORDER BY "date:날짜:start" DESC LIMIT 3
```

- 맨 위 행이 **원본**입니다.
- 원본의 날짜가 **기준일과 같거나 그 이후**면 이미 이번 주 페이지가 있는 것이니
  아무것도 만들지 말고 "이미 있음: [제목] (날짜)" 한 줄로 끝냅니다. 사람이 먼저
  만들어 둔 경우가 여기 해당하며, 중복 생성이 가장 피해야 할 실수입니다.

### 3. 새 제목을 정한다

원본 제목에서 `[WEEK N]` 의 N 을 읽습니다 (`[WEEK 4~5]` 처럼 범위면 뒤 숫자).

- 원본 날짜의 **달과 기준일의 달이 같으면** N+1
- **달이 바뀌었으면** 1

새 제목은 정확히 `[WEEK N]` 형식입니다. 대괄호·공백·대문자 그대로, 뒤에 아무것도
붙이지 않습니다. 원본 제목에서 N 을 읽을 수 없으면 기준일이 그 달의 몇 번째
월요일인지(`(일 - 1) // 7 + 1`)로 정하고 보고에 그 사실을 적습니다.

> 왜 '몇 번째 월요일'이 아니라 '지난 번호 + 1' 인가: 공휴일로 한 주를 건너뛰거나
> 화요일에 회의한 달(2026-05, 2026-08)에 팀은 '그 달 몇 번째 회의'로 번호를 매겼습니다.
> 지난 번호 + 1 이 그 관행과 일치합니다.

### 4. 복제한다

`notion-duplicate-page` 에 원본 page id 를 넘깁니다. 복제본은 같은 DB 안에
`[WEEK N] (1)` 제목으로 생기고 날짜·참석자·본문·아이콘이 전부 따라옵니다.
복제는 비동기라 바로 비어 있을 수 있습니다.

### 5. 속성이 채워질 때까지 기다린다

15초쯤 기다렸다가 2단계와 같은 SQL 에 `WHERE url = '<복제본 url>'` 를 걸어
`주` 값이 들어왔는지 봅니다. 비어 있으면 15초 간격으로 최대 6번까지만 다시
봅니다. 그래도 비어 있으면 복제본 링크와 함께 실패로 보고하고 끝냅니다 —
속성이 없는 상태에서 덮어쓰면 제목만 있고 본문이 없는 페이지가 될 수 있습니다.

### 6. 제목과 날짜를 바꾼다

`notion-update-page` / `update_properties`, `allow_async: false`:

```json
{"주": "[WEEK N]", "date:날짜:start": "YYYY-MM-DD", "date:날짜:is_datetime": 0}
```

참석자·아이콘·본문은 건드리지 않습니다.

### 7. 확인하고 보고한다

5단계 SQL 을 한 번 더 돌려 제목과 날짜가 바뀐 것을 확인한 뒤, 한 줄로 보고합니다:
`생성: [WEEK N] (YYYY-MM-DD) <링크> ← 원본 [WEEK M] (날짜)`.

## 하지 않는 것

- 원본 페이지를 수정하거나 지우지 않습니다.
- 복제본 본문을 고치지 않습니다. 체크 표시를 풀거나 지난주 내용을 비우지 않습니다 —
  팀이 손으로 할 때도 그대로 두었습니다.
- 같은 날짜의 페이지가 있으면 만들지 않습니다. 애매하면 만들지 않는 쪽을 택합니다.
- DB 템플릿(`[WEEK N]`)을 쓰지 않습니다. 사용자는 템플릿이 아니라 **지난주 페이지**를
  복제하길 원합니다.
- 같은 도구 호출을 3번 이상 재시도하지 않습니다.

## 공휴일

월요일이 공휴일이라 화요일에 회의하면 날짜가 월요일로 들어가 있을 것입니다.
팀이 노션에서 날짜만 하루 밀면 됩니다. 자동화는 공휴일을 판단하지 않습니다.
