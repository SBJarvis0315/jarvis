# 마스터 시트 발행 로그 기입

고객사와 함께 보는 구글 스프레드시트의 **`7) 발행 로그`** 탭에, 노션 플래너에서
발행이 끝난 글을 한 줄씩 옮겨 적습니다.

| 마스터 시트 | 노션 플래너 |
| --- | --- |
| 날짜 | 발행 예정일 |
| 콘텐츠 유형 | 유형 |
| 제목 | 제목 |
| 게재본 | URL |

## 먼저 확인할 것

이 일은 구글 Apps Script로 도는 경로(`apps-script/`)와 파이썬으로 도는 경로
(`notion-wp-publish/`) 둘 중 하나로 설정되어 있습니다. **Apps Script 트리거가 이미
걸려 있으면 아래 명령을 돌리지 마세요** — 같은 일을 두 번 하는 것입니다
(중복은 걸러지지만 의미가 없습니다). 어느 쪽인지 모르면 사용자에게 물어보세요.

## 실행 방법

작업 디렉터리는 `notion-wp-publish/` 입니다.

```bash
cd notion-wp-publish
PYTHONPATH=src python3 -m notionwp.sheetsync --dry-run   # 무엇이 들어갈지만 확인
PYTHONPATH=src python3 -m notionwp.sheetsync             # 실제 기입
```

대상 고객사는 `config/sheet-log.json` 에서 읽습니다. 한 번 실행하면 거기 적힌
고객사를 전부 처리하고, `--client 제로클리닉` 처럼 이름 일부를 넘기면 한 곳만 돕니다.

**처음 도는 고객사이거나 시트 모양이 바뀐 것 같으면 `--dry-run` 을 먼저 돌리세요.**
고객사가 함께 보는 문서라 잘못 적히면 눈에 띕니다.

## 무엇이 기입되는가

- **URL이 채워진 행**을 발행이 끝난 것으로 봅니다. 진행 상황은 보지 않습니다
  (플래너마다 상태 이름이 달라서입니다).
- 제목·유형·날짜 중 하나라도 비어 있으면 기입하지 않고 실행 결과에 남깁니다.
  그건 사람이 플래너를 채워야 하는 상황입니다.
- **이미 적힌 줄은 건드리지 않습니다.** 제목과 게재본이 둘 다 빈 줄에만 씁니다.
- **게재본 주소로 중복을 거릅니다.** 몇 번을 돌려도 같은 글이 두 줄이 되지 않습니다.

## 결과 보고

명령이 끝나면 고객사별 요약이 출력됩니다. 아래 형식으로 정리해서 보고하세요.

- **기입한 글**: 몇 건인지, 제목 목록
- **보류된 글**: 제목과 어떤 칸이 비어 있는지 (사람이 플래너를 채워야 합니다)

기입이 0건이고 보류도 없으면 "새로 기입할 것 없음" 한 줄로 끝내세요.

노션 '자동화 실행 로그' DB에는 **스크립트가 알아서 한 줄을 남깁니다**
(단계 = 마스터 시트 기록). 직접 로그 행을 만들지 마세요.

## 실패했을 때

| 메시지 | 원인 | 대처 |
|---|---|---|
| `환경변수가 비어 있습니다: GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스 계정 키 미설정 | README 9장 ①·④ 참고 |
| `시트에 접근할 수 없습니다 (403/404)` | 시트를 서비스 계정에 공유하지 않음 | 메시지에 나온 주소를 시트에 **편집자**로 추가 |
| `Could not find database ... shared with your integration` | 플래너에 노션 통합 미연결 | 플래너 `⋯` → 연결 → 통합 선택 |
| `헤더 줄을 찾지 못했습니다` | 탭 이름이 다르거나 헤더 문구가 바뀜 | `config/sheet-log.json` 의 `sheet`·`columns` 확인 |
| `cryptography 가 설치되어 있지 않습니다` | 의존성 미설치 | `pip install -r requirements.txt` |

## 하지 말아야 할 것

- 시트를 손으로 고치지 마세요. 값이 잘못됐으면 **노션 플래너를 고치고** 다시 돌립니다.
- 이미 적힌 줄을 지우거나 옮기지 마세요. 스크립트는 빈 줄만 채웁니다.
- 스크립트를 우회해 구글 시트 API를 직접 호출하지 마세요. 중복 검사와 실행 로그가 빠집니다.
