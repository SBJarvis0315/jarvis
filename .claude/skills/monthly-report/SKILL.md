# 월간 리포트 자동 작성

매달 1일, **직전 달**의 작업 성과를 **그 달 말일 기준 소하 데이터**로 보고합니다.
10월 1일에 돌면 대상은 2026년 9월, 데이터 기준일은 9월 30일, 플래너 필터의
작업년월은 `2026.9`, 리포트명은 `26.09 고객사명 리포트` 입니다.

작업 디렉터리는 `monthly-report/` 입니다.

```bash
cd monthly-report
PYTHONPATH=src python3 -m monthlyreport --client 참포도나무병원 period
```

`period` 는 대상 달·기준일·플래너 옵션·CSV 파일명을 JSON 으로 찍습니다.
**연월을 손으로 계산하지 마세요.** 시험할 때는 `--month 2026-08` 또는
`--run-on 2026-10-01` 로 가장합니다.

## 이 스킬이 하는 일과 하지 않는 일

| 구간 | 누가 |
|---|---|
| 플래너 표 '작업년월' 필터 | **자동** |
| 소하 CSV 3종 수집·리포트 페이지 첨부 | **자동** (프로파일 필요, 아래 참고) |
| 요약 표(SoV·커버리지)·지표 설명 빈칸 | **자동** |
| n월에 새로 인용/언급된 질문 목록 | **자동** (전월 CSV 대비 diff) |
| 월간 GEO/AEO 현황 분석 본문 | **자동** |
| 내부 공유용 빨간 콜아웃 삭제 | **자동** |
| 소하 개요·Top3 캡쳐(빨간 테두리) | 사람 |
| 구글 SEO 성과 표(서치콘솔) | 사람 |
| 네이버 블로그 통계 | 사람 (캡챠) |
| 특이사항·차월 목표 | 사람 |
| 우피 링크 확인·발송, 상태 '완료' | 사람 |

마지막 네 줄은 **손대지 마세요.** 자동화가 끝나면 남은 항목을 사용자에게 목록으로
알려 주고 멈춥니다.

## 표준 절차

### 1단계 — 대상 달과 리포트 페이지

`period` 로 대상 달을 받습니다. 리포트 페이지는 **매달 28일 오전 6시에 노션 자동화가
이미 만들어 둡니다.** 리드젠랩 월간 리포트 DB에서 그 달 그 고객사 행을 찾아 씁니다.

- **복제하지 마세요.** 자동 생성된 페이지를 그대로 편집합니다.
- 같은 달 행이 둘 이상이거나 하나도 없으면 **멈추고 사용자에게 물어보세요.**
- 첫 달(콘텐츠 발행 전) 고객사는 '기본 리포트 템플릿 - 콘텐츠 발행 전' 양식을 쓰므로
  이 스킬을 돌리지 말고 사용자에게 알립니다.

### 2단계 — 콘텐츠 플래너 필터의 작업년월

리포트 페이지에는 SEO(Google)·SEO(Naver) 두 개의 플래너 표가 이미 걸려 있습니다.
고객사별 필터(유형·진행 상황)는 사람이 미리 맞춰 뒀으므로 **작업년월만** 바꿉니다.

1. 페이지를 `fetch` 해서 `<database url=...>` 두 개를 찾습니다.
2. 각 database 를 `fetch` 해서 `<view url="view://...">` 와 현재 `simpleFilters` 를 읽습니다.
3. **읽은 필터를 전부 그대로 다시 쓰되 작업년월만 바꿔서** `update_view` 를 부릅니다.

```
CLEAR FILTER; FILTER "작업년월" = "2026.9"; FILTER "유형" IN ("롱폼", "엔티티", "숏폼"); FILTER "진행 상황" = "Complete"
```

네이버 표는 `FILTER "유형" IN ("네이버", "네이버(UGC)")` 입니다.

> **작업년월 하나만 넘기면 나머지 필터가 날아갑니다.** `configure` 는 기존 필터를
> 고치는 게 아니라 통째로 갈아끼웁니다. 그래서 읽은 값을 전부 다시 써야 합니다.
> 갈아끼운 뒤에는 노션이 이를 '고급 필터'로 저장합니다. 걸리는 행은 같지만 화면의
> 필터 칩 모양이 달라질 수 있으니, 처음 도입할 때 사람이 한 번 눈으로 확인합니다.

원본 콘텐츠 플래너 DB의 데이터는 **절대 건드리지 않습니다.** 뷰 필터만 바꿉니다.

### 3단계 — 소하에서 데이터 수집

```bash
PYTHONPATH=src python3 -m monthlyreport --client 참포도나무병원 --month 2026-09 \
  collect --out work/champodonamu-2026-09
```

계정은 `SOHA_USER_<약칭>` / `SOHA_PASSWORD_<약칭>` 환경변수에서 읽습니다. 없으면
리포트 템플릿의 'AEO/GEO 트래킹 대시보드' 콜아웃에 적힌 값을 `--soha-user`,
`--soha-password` 로 넘깁니다.

받는 것은 **프롬프트·브랜드·데이터소스 탭 CSV 3종**과 개요·브랜드 대시보드 캡쳐입니다.

> **아직 화면 프로파일이 비어 있습니다.** `src/monthlyreport/profiles/soha.json` 이
> 채워지기 전에는 `collect` 가 돌지 않습니다. 먼저 정찰하세요:
>
> ```bash
> PYTHONPATH=src python3 -m monthlyreport inspect --slug champodonamu --out inspect/champodonamu
> ```
>
> 결과(`inspect.json`·스크린샷·HTML)를 보고 프로파일을 채운 뒤 `inspect/NOTES.md` 에
> 무엇을 보고 무엇을 골랐는지 남깁니다. 선택자를 **추측해서 넣지 마세요.**

### 4단계 — CSV 보관

받은 CSV 3종을 **리포트 페이지에 첨부**합니다. 익월 작업이 전월 CSV를 여기서 꺼내
쓰므로, 이 단계를 건너뛰면 다음 달 전월 대비 분석이 불가능해집니다.

전월 CSV 는 전월 리포트 페이지의 첨부에서 가져옵니다. 없으면 전월 비교 없이
단월 분석으로 진행하고, 그 사실을 리포트에 밝힙니다.

### 5단계 — 요약 표와 지표 설명

`collect` 가 남긴 `metrics.json` 의 값으로 채웁니다.

- **SoV 세부 데이터** 표: 전월·현월·비교, 총 경쟁 브랜드 수, 브랜드 순위, 언급 비율
- **GEO 커버리지율** 표: 전월·현월·비교, 세팅 질문 수, 언급된 질문 수
- **지표 설명** 토글의 빈칸(`____`): 커버리지율, SoV, Visibility Score, GEO 순위

전월 값은 **전월 리포트 페이지에 적힌 수치를 그대로** 씁니다. 소하에서 다시 뽑지
마세요. 같은 대행사 리포트인데 비교 기준이 달라 보이면 고객사가 의심합니다.

비교 칸은 오를 때 파란색 `⬆︎`, 내릴 때 빨간색 `⬇︎` 입니다 (`10.9% ⬆︎`).

### 6단계 — n월에 새로 인용/언급된 질문

전월 CSV 에는 없고 당월 CSV 에는 있는 프롬프트를 뽑습니다. 상위 10건은 질문 ·
인용 콘텐츠 URL · 인용 채널을 풀어 쓰고, 나머지는 번호 · 프롬프트 · 채널 3열 표로
정리한 뒤 "나머지 N건은 약식으로 인용 채널만 작성해두었습니다" 를 덧붙입니다.

### 7단계 — 분석 본문

`월간 AEO·GEO 현황 분석 방법` 문서의 표준 프롬프트를 그대로 따릅니다. 요약하면:

- 모든 수치는 CSV 를 **직접 집계**합니다. 눈대중·추정 금지, 작성 전 재집계로 자기 검증.
- 사실과 추론을 구분합니다. 추론은 "~로 추정됩니다".
- 표본 5개 미만 카테고리는 표본 수를 밝히고 참고치로만 씁니다.
- 구조: 분석 개요 → 종합 요약 → 1. 미인용 및 공백 → 2. 인용 프롬프트 →
  3. 브랜드 순위 → 추가 제안.
- **어투**: 합니다체 보고문. em-dash(—) 금지, 본문 별표 강조 금지, AI 상투어 금지.
- 강조는 꼭 필요한 곳만. 긍정은 파란색 볼드, 부정은 빨간색 볼드.

쓰고 나서 검증 체크리스트를 돌립니다. 종합 점유율이 브랜드 CSV 원본과 맞는지,
완전 미인용 수·비율이 맞는지, 도메인 인용과 브랜드명 언급의 격차가 들어갔는지,
전월 대비 변화가 수치와 함께 적혔는지.

### 8단계 — 내부용 콜아웃 삭제

빨간 배경 '담당자에게 전하는 말' 콜아웃은 **전부 지웁니다.** 고객사가 보는
문서입니다. 회색 '참고사항'·'트래킹 대시보드' 콜아웃은 남깁니다.

### 9단계 — 남은 일 보고

사람이 해야 할 것(캡쳐 3종, 구글 서치콘솔 표, 네이버 통계, 특이사항·차월 목표,
우피 링크 확인·발송, 상태 '완료')을 목록으로 알리고 멈춥니다. **상태를 '완료'로
바꾸지 마세요.** 보고가 끝났다는 뜻이라 사람이 눌러야 합니다.

## 인자 해석

- 고객사 이름을 말하면 `--client` 로 넘깁니다.
- "8월 리포트" 처럼 달을 말하면 `--month 2026-08` 로 넘깁니다. 말하지 않으면
  실행일의 직전 달입니다.
- 여러 고객사를 한 번에 돌릴 때도 **한 고객사를 끝내고 다음으로** 갑니다. 중간에
  섞이면 어느 리포트에 어느 수치를 넣었는지 추적할 수 없습니다.

## 멈춰야 할 때

- 리포트 페이지를 못 찾거나 같은 달 행이 둘 이상일 때
- 소하 로그인이 실패할 때 (비밀번호가 바뀌었을 수 있습니다)
- 전월 CSV 가 없고 첫 달도 아닐 때
- CSV 집계값이 소하 화면 수치와 어긋날 때

어느 경우든 **추정으로 채우지 말고** 사용자에게 무엇이 어긋났는지 알립니다.
