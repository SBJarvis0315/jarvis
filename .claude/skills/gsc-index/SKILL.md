# 자동 색인 요청 — 노션 쪽 절반

구글 서치콘솔의 '색인 생성 요청' 버튼은 공개 API가 없어서 브라우저로 눌러야 합니다.
그 클릭만 aside가 맡고, **플래너를 읽고 쓰는 일은 전부 이 스킬이 노션 API로** 처리합니다.

```
19:30  적재  이 스킬 →  8개 플래너에서 대상 행을 찾아 대기열에 씀
20:00        aside   →  대기열 '① aside 작업 목록' 탭만 보고 GSC 처리, 결과·스크린샷 기입
21:00  반영  이 스킬 →  대기열 '② Claude 반영 대기' 탭을 읽어 플래너에 되돌려 씀
```

두 모드는 **반드시 분리해서** 돕니다. 적재 직후에 반영을 돌리면 aside가 아직 아무것도
하지 않았으므로 할 일이 없습니다.

## 실행 방법

`/gsc-index 적재` 또는 `/gsc-index 반영` 으로 부릅니다. 인자가 없으면 **무엇을 할지 물어보세요.**
고객사 이름을 함께 말하면 그 고객사만 처리합니다.

노션 접근은 전부 Notion MCP 도구(`notion-query-data-sources`, `notion-create-pages`,
`notion-update-page`, `notion-create-comment`, `notion-create-file-upload`,
`notion-download-attachment`)로 합니다. 브라우저를 열지 마세요.

## 대상

### 색인 대기열

| | |
|---|---|
| 데이터소스 | `collection://1c09fede-4164-46ba-81bc-9702a2d0d578` |
| 페이지 | https://app.notion.com/p/a1a88df0f348409e959f60d3202942d4 |

속성은 여덟 개뿐입니다.

| 속성 | 타입 | 누가 |
|---|---|---|
| 항목 | 제목 | 적재 — 플래너 행의 제목 그대로 |
| 고객사 | 선택 | 적재 |
| 요청 URL | URL | 적재 |
| 원본 행 | URL | 적재 — 플래너 행 링크. 반영할 위치 |
| 색인 요청 | 선택 (대기·완료·오류·개수 제한) | 적재는 '대기', 결과는 aside |
| 결과 메시지 | 텍스트 | aside |
| 스크린샷 | 파일 | aside |
| 반영 완료 | 체크박스 | 반영 |

### 고객사 플래너

**처리 순서 = 아래 순서.** 서치콘솔 할당량은 계정 전체에 걸릴 수 있어 뒤쪽이 밀립니다.

| # | 고객사 | 데이터소스 |
|---|---|---|
| 1 | 클리어톤의원 | `collection://5ec68fa2-06ff-8312-ad80-878accfa81b4` |
| 2 | 참포도나무병원 | `collection://37568fa2-06ff-812b-a99c-000b2831bb7b` |
| 3 | 클리어서울안과 | `collection://37d68fa2-06ff-81ef-b7ed-000bf520e760` |
| 4 | 큐라엘 | `collection://37a68fa2-06ff-81aa-a4f1-000bfa673325` |
| 5 | 쉬즈메디병원 | `collection://88c68fa2-06ff-8373-917d-8784bc0bfb4d` |
| 6 | 비컴성형외과 | `collection://64f68fa2-06ff-83c0-a269-87a97af4722c` |
| 7 | 지혜로운 필라테스 | `collection://88d68fa2-06ff-829f-a7ca-0754351e8f00` |
| 8 | 제로클리닉 | `collection://33968fa2-06ff-83c9-9264-0735823732c7` |

여덟 곳 모두 `색인 요청`(대기·완료·오류·개수 제한), `유형`, `userDefined:URL`, `제목` 을
같은 이름으로 갖고 있습니다. 데이터소스 ID가 안 맞으면 플래너가 새로 만들어진 것이니,
플래너를 `notion-fetch` 로 열어 새 ID를 확인하고 **이 표를 고쳐서 커밋하세요.**

**새 고객사는 이 표에 추가되기 전까지 대상이 아닙니다.** 표에 없으면 오류도 나지 않고
요약에도 안 잡혀서 누락을 알아채기 어렵습니다. 도입 시 이 표와 아래 요약 형식을 함께 고칩니다.

## 적재 모드

### 1. 대상 행 찾기

고객사마다 아래 쿼리를 돌립니다. 플래너의 '진행중'·'완료' 탭을 흉내 낼 필요는 없습니다 —
탭은 사람이 보는 화면일 뿐이고, 판정 조건은 URL과 색인 요청 두 가지뿐입니다.

```sql
SELECT url, "제목", "userDefined:URL", "유형", "색인 요청"
FROM "collection://…"
WHERE "색인 요청" IN ('대기', '개수 제한')
  AND "userDefined:URL" IS NOT NULL
  AND "userDefined:URL" != ''
```

`url` 이 그 행의 페이지 주소이고, 대기열의 `원본 행` 에 그대로 넣습니다.

### 2. 타 플랫폼 건 걸러내기

아래에 해당하면 **대기열에 넣지 않습니다.** 상태도 바꾸지 않고 요약에도 언급하지 않습니다.
우리가 소유권을 확인한 서치콘솔 속성이 아니라 색인 요청 자체가 불가능합니다.

- `유형` 이 `네이버` 또는 `네이버(UGC)`
- URL 도메인이 naver.com · blog.naver.com · m.blog.naver.com · post.naver.com ·
  cafe.naver.com · tistory.com · brunch.co.kr · story.kakao.com · blog.me 계열

유형과 도메인 중 하나만 걸려도 제외합니다. 유형이 비어 있으면 도메인으로 판단합니다.

### 3. 대기열에 쓰기

남은 행을 **`색인 요청` = '대기'** 로 대기열에 만듭니다. 순서가 곧 aside의 처리 순서입니다.

1. **전날 '개수 제한'으로 밀린 행을 맨 앞에** 놓습니다 (플래너 값이 '개수 제한'인 행)
2. 그다음 나머지 '대기' 행을 고객사 순서대로

같은 URL이 대기열에 **이미 '대기' 상태로 남아 있으면 다시 만들지 마세요.** 전날 aside가
처리하지 못하고 남긴 것이므로 그대로 두면 됩니다.

플래너 쪽 값은 **적재 단계에서 건드리지 않습니다.** 상태 변경은 결과가 나온 뒤 반영 모드에서만 합니다.

### 4. 보고

```
색인 대기열 적재 완료 — 총 N건
- 클리어톤의원 3건 / 참포도나무병원 0건 / …
(전날 개수 제한 재시도 2건 포함)
```

0건이면 "적재할 건 없음" 한 줄로 끝냅니다.

## 반영 모드

### 1. 결과 읽기

```sql
SELECT url, "항목", "고객사", "요청 URL", "원본 행", "색인 요청", "결과 메시지", "스크린샷"
FROM "collection://1c09fede-4164-46ba-81bc-9702a2d0d578"
WHERE "반영 완료" != '__YES__'
  AND "색인 요청" != '대기'
```

`색인 요청` 이 아직 '대기'인 행은 **aside가 처리하지 않은 것**이므로 건너뜁니다.
반영하지도, 요약에 넣지도 마세요. 다음 실행 때 다시 봅니다.

### 2. 플래너 행에 되돌려 쓰기

행마다 **댓글 먼저, 상태 나중**입니다. 순서가 바뀌면 상태만 바뀌고 사유가 안 남을 수 있습니다.

1. **스크린샷 옮기기** — 대기열 행에 파일이 있으면 `notion-download-attachment` 로 내려받고,
   `notion-create-file-upload` 로 다시 올려 댓글에 첨부합니다. 파일이 없으면 텍스트만 남깁니다.
2. **댓글** — `원본 행` 페이지에 `notion-create-comment` 로 남깁니다.
   `selection_with_ellipsis` 없이 페이지 댓글로 답니다. (셀 댓글은 API로 달 수 없습니다.)

   ```
   색인 요청 결과: 완료
   URL: https://…
   처리: 2026-08-25 20:04
   메시지: 색인 생성 요청됨
   ```

   실패했으면 `결과 메시지` 를 그대로 옮깁니다. 요약하거나 다듬지 마세요 — 매니저가
   구글 문구 그대로를 봐야 원인을 찾습니다.
3. **상태** — `원본 행` 의 `색인 요청` 을 대기열 값과 **똑같이** 씁니다.
   양쪽 선택지가 대기·완료·오류·개수 제한으로 동일하므로 변환하지 않습니다.
4. **대기열 행의 `반영 완료` 체크** — 여기까지 끝난 뒤에 체크합니다.

`원본 행` 이 비어 있으면 되돌려 쓸 위치가 없습니다. 상태를 바꾸지 말고 요약에 남기세요.

### 3. 요약 출력

**이 형식을 그대로 지키세요.** 매니저가 매일 이 형태로 확인합니다.
처리 대상이 0개인 고객사도 '0개'로 여덟 곳 전부 적습니다.

```
당일 총 색인 필요 링크 수: N개
- 클리어톤의원: n개
- 참포도나무병원: n개
- 클리어서울안과: n개
- 큐라엘: n개
- 쉬즈메디병원: n개
- 비컴성형외과: n개
- 지혜로운 필라테스: n개
- 제로클리닉: n개

당일 총 색인 완료 링크 수: N개
당일 총 색인 미완료 링크 수: N개 (개수 제한 X개 / 오류 Y개)
```

집계에 넣는 것은 **대기열에 올라간 자사 도메인 건만**입니다. 타 플랫폼 건과 조건 미충족
행은 숫자에 넣지 않습니다.

## 하지 말아야 할 것

- **브라우저로 노션을 조작하지 마세요.** 이 스킬은 전부 API로 합니다. 셀에 마우스를 올리거나
  드롭다운을 클릭하는 동작은 aside 몫이었고, 이제 필요 없습니다.
- **서치콘솔에 직접 접속하지 마세요.** 로그인 세션이 없어 실패합니다. 색인 요청은 aside가 합니다.
- **`색인 요청` 이 '대기'인 대기열 행을 임의로 '완료'로 바꾸지 마세요.** aside가 실제로
  버튼을 눌렀는지 확인할 방법이 없습니다.
- **조건 미충족 행(URL 없음, 색인 요청이 대기가 아님)과 타 플랫폼 건을 보고하지 마세요.**
  매일 같은 행이 쌓여 요약을 못 쓰게 됩니다.
- **결과 메시지를 고쳐 쓰지 마세요.** 구글 문구 그대로 옮깁니다.

## 자주 나오는 상황

| 상황 | 뜻 | 조치 |
|---|---|---|
| 대기열에 '대기'로 남은 행이 있음 | aside가 안 돌았거나 중간에 끊김 | 그대로 두면 다음 실행에서 처리됩니다. 이틀 이상이면 보고 |
| 반영할 행이 0건 | aside가 아직 처리 전 | "반영할 결과 없음" 한 줄로 끝냅니다 |
| 여러 고객사가 통째로 '개수 제한' | 할당량 소진 후 일괄 처리 | 정상입니다. 다음 날 최우선으로 다시 적재됩니다 |
| 결과 메시지에 속성이 없다는 내용 | 자사 도메인인데 GSC에 속성 미등록 | '오류'로 반영하고, 요약 아래 담당 매니저 확인 필요로 한 줄 덧붙이기 |
| 쿼리가 데이터소스를 못 찾음 | 플래너가 새로 만들어짐 | `notion-fetch` 로 새 ID 확인 후 위 표 수정 |
