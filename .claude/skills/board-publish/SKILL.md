# 자체 게시판 자동 발행

노션 피드백 플래너는 워드프레스 고객사와 **똑같이** 쓰되, 발행처만 다릅니다.
고객사 홈페이지 제작사의 관리자 화면(게시판관리 › 블로그 › 글쓰기)에 브라우저로
들어가 팀원이 손으로 하던 일을 그대로 합니다.

```
로그인 → 게시판 탭 → 글쓰기 → 이미지 업로드 → </> 코드 보기에 HTML →
조회수·제목 → 등록 → 목록에서 글 번호 확인 → 플래너 게재완료 + URL
```

## 실행 방법

작업 디렉터리는 `notion-wp-publish/` 입니다. 브라우저 자동화 라이브러리가 있어야 합니다.

```bash
cd notion-wp-publish
pip install -q playwright        # 이미 있으면 바로 끝납니다. 브라우저는 환경에 있는 Chromium 을 씁니다
PYTHONPATH=src python3 -m notionwp --board --prepare work/
```

대상 고객사는 노션 '고객사 설정표'에서 상태가 활성이고, **'워드프레스 주소' 칸에 적힌 사이트의
게시판 프로파일이 저장소에 있는** 곳입니다. 설정표의 발행 주소 칸은 워드프레스와 **같은 칸
하나**이고, 어느 쪽인지는 `boards/<호스트>.json` 이 있는지로 갈립니다. 프로파일이 없는
사이트는 워드프레스로 보고 `/wp-publish` 가 가져갑니다.

| 플래그 | 동작 |
|---|---|
| `--board --dry-run` | 조건 판정만. 브라우저도 띄우지 않음 |
| `--board --prepare DIR` | 이미지를 내려받고 `plan.json` 생성. 아무것도 발행하지 않음 |
| `--board --plan DIR` | 검수한 ALT로 **공개 발행** + 노션 게재완료·URL 기록 |
| `--board-inspect DIR` | 관리자에 로그인해 화면·폼 구조를 DIR 에 떠 둠. 발행 안 함 |
| `--client 제로` | 그 고객사만 |

**게시판에는 임시저장이 없습니다.** `--draft` 는 쓸 수 없고, `--plan` 으로 돌리면
곧바로 공개됩니다. 그래서 ALT 검수 단계를 건너뛰지 마세요.

## 표준 절차 — 워드프레스와 같은 3단계

### 1단계 — 준비

```bash
PYTHONPATH=src python3 -m notionwp --board --prepare work/
```

### 2단계 — 이미지를 보고 ALT 작성 (당신이 할 일)

`work/<페이지ID>/plan.json` 의 `images[].preview` 를 Read 도구로 하나씩 열어 실제로 보고
`alt` 를 채웁니다. 규칙은 `/wp-publish` 스킬의 2단계와 같습니다 — 실제로 보이는 것,
놓일 섹션과 맞물리게, 한국어 20~50자, 의료광고 규정(전후 비교·효과 단정 금지).
`thumbnail_alt` 도 채웁니다. 숏폼은 `images` 가 비어 있는 것이 정상이며 썸네일이
본문 맨 위 사진이 됩니다.

`video_candidates` 는 게시판 발행에서는 비어 있습니다. 영상은 넣지 않습니다.

### 3단계 — 발행

```bash
PYTHONPATH=src python3 -m notionwp --board --plan work/
```

## 발행 조건

워드프레스 게이트와 같되 **슬러그는 필요 없습니다** (글 주소가 번호로 정해집니다).

- 진행 상황 = `컨펌 진행 중`
- 제목 · 원고 본문 · 발행 예정일(오늘 이하)
- 썸네일 · 본문 이미지(숏폼은 썸네일만) · 메타타이틀 · 메타디스크립션

## 게시판에 올라가는 글의 형식

팀이 손으로 올리던 형식을 그대로 따릅니다. 스크립트가 만들며 손댈 필요 없습니다.

- `<title>` + `<meta name="description">` 을 본문 맨 위에 넣습니다 (팀 관행. 사이트
  `<head>` 에는 반영되지 않는다는 것을 팀도 알고 있습니다)
- `<h1>`/`<h2>`/`<h3>` 에 인라인 `font-size`·`margin` — 줄바꿈으로 간격을 주면 h 태그가 씹힙니다
- 리스트는 `<ul>`/`<ol>` 대신 `<p>• …</p>` — 사이트 템플릿에서 서식이 깨집니다
- 이미지는 `<p><br></p><div><img src alt></div>` — 서버에 올라간 주소만 씁니다
- **조회수는 500~1100 사이 임의 값**으로 채웁니다 (사용자 지시)
- 공지/일반은 `일반`, HTML 모드는 `HTML` 그대로

## 중복 발행 방지

워드프레스처럼 노션 ID 를 글에 각인할 곳이 없어 **제목**으로 대조합니다. 등록 전에
관리자 목록에서 같은 제목을 찾고, 있으면 다시 올리지 않고 플래너만 게재완료로 맞춥니다
(지난 회차에 등록까지 되고 노션 쓰기만 실패한 경우를 되살리는 길이기도 합니다).
그러므로 같은 제목의 원고가 둘이면 두 번째는 발행되지 않습니다.

## 사이트 프로파일 — `boards/<호스트>.json`

관리자 화면은 제작사마다 다르므로 사이트별 생김새를 프로파일에 굳혀 둡니다
(썸네일 디자인 파일과 같은 방식). 제로클리닉은 `boards/www.zeroclinic1.com.json` 입니다.

| 키 | 뜻 |
|---|---|
| `admin_url` | 글 목록 화면 주소. 설정표에 경로까지 적혀 있으면 그쪽이 우선 |
| `login_url` | 로그인 화면 주소 |
| `public_url` | 공개 글 주소. `{id}` 자리에 글 번호 |
| `tab` | 목록에 들어간 뒤 누를 게시판 탭 글자. 목록 주소가 정확하면 비워 둠 |
| `write_button` / `submit_buttons` | 글쓰기·등록 버튼 글자 (그림 버튼은 `alt` 로 찾음) |
| `submit_selector` | 등록 버튼을 곧바로 집는 CSS 셀렉터 — 글자로 못 찾는 그림 버튼용 |
| `id_param` | 목록의 글 링크에서 번호를 읽는 쿼리 이름 (`id`) |
| `labels` | 글쓰기 폼의 행 머리글 (제목·조회수·내용·HTML) |
| `html_mode` / `html_mode_value` | HTML 라디오를 고를 글자 / 값. 값이 있으면 값이 우선 |
| `hit_min` / `hit_max` | 조회수 범위 |

제로클리닉 프로파일은 실제 관리자를 열어 확인한 값입니다. 무엇을 확인했는지는
`boards/inspect/zeroclinic/NOTES.md` 에 있습니다. 그 사이트에서 문제가 생기면 이 문서부터
읽으세요 — 발행 게시판이 `boardseo_list.php` 인 것(같은 이름의 `blog_list.php` 는 다른
빈 게시판), 등록 버튼이 그림인 것, 본문이 `contents` 로 넘어가는 것이 적혀 있습니다.

### 프로파일이 없는 고객사가 나오면 (당신이 할 일)

`'○○' 게시판 프로파일이 없습니다` 오류가 나면:

**프로파일이 없으면 그 고객사는 아예 이 단계에 잡히지 않습니다** (워드프레스로 분류되어
`/wp-publish` 에서 mu-plugin 오류가 납니다). 새 자체 게시판 고객사가 생기면 프로파일부터
만들어야 합니다.

1. 설정표의 '워드프레스 주소' 를 `--board-inspect` 에 쓰기 위해 `--client ○○` 로 지정하고
   `PYTHONPATH=src python3 -m notionwp --board-inspect work/inspect --client ○○` 를 돌립니다.
   `work/inspect/<고객사>/inspect.json` 에 폼 필드 목록(이름·행 머리글), 에디터 종류,
   목록 링크가 담기고 스크린샷이 함께 남습니다. Read 도구로 스크린샷을 직접 보세요.
2. `boards/www.zeroclinic1.com.json` 을 복사해 그 사이트에 맞게 고칩니다. 대개 `public_url`,
   `tab`, `labels` 정도만 다릅니다.
3. `--board --dry-run` 으로 대상이 잡히는지 보고, 커밋합니다. 사람에게 묻지 마세요.

### 자동화가 깨졌을 때

사이트가 개편되면 셀렉터가 어긋납니다. 실패 메시지에 `(화면: work/board/….png)` 가
붙어 있으니 **그 스크린샷을 먼저 열어보세요.** 어디서 멈췄는지 보이면 프로파일이나
`src/notionwp/board.py` 의 해당 단계를 고칩니다. `--board-inspect` 로 새 구조를 뜨는 것이
가장 빠릅니다.

## 결과 보고

`/wp-publish` 와 같은 형식으로 정리합니다.

- **발행된 원고**: 제목과 링크
- **실패한 원고**: 제목·원인·사람이 할 일. 실패 행은 플래너에서 자동으로 `발행 오류`
- **조건 미달로 대기 중인 원고**: 비어 있는 항목

발행 0건이고 대기도 없으면 "게시판 발행 대상 없음" 한 줄로 끝냅니다.
실행 로그는 스크립트가 '자동화 실행 로그' DB 에 남깁니다(단계 = **게시판 발행**).
직접 로그 행을 만들지 마세요.

## 실패했을 때

| 메시지 | 원인 | 대처 |
|---|---|---|
| `게시판 발행 대상 고객사가 없습니다` | 설정표에 활성 + 게시판 주소가 있는 행이 없음 | 설정표 확인 |
| `관리자 계정이 없습니다 … BOARD_USER_○○` | 환경변수 미설정 | 메시지에 나온 두 이름으로 환경변수 추가 |
| 계정은 맞는데 `패스워드가 틀립니다` | 비밀번호의 기호(`#`·`@` 등)가 환경변수 칸을 지나며 상함 | `BOARD_PASSWORD_○○_B64` 에 Base64 로 넣기 (아래 참고) |
| `…_B64 값을 Base64 로 읽지 못했습니다` | 비밀번호를 그대로 `_B64` 에 넣음 | Base64 로 바꿔서 넣기 |
| `로그인에 실패했습니다` | 아이디·비밀번호 오류, 또는 사이트가 허용 도메인에 없음 | 자격증명 확인. 스크린샷이 빈 화면이면 네트워크 허용 목록에 그 호스트 추가 |
| `게시판 프로파일이 없습니다` | 새 사이트 | 위 「프로파일이 없는 고객사가 나오면」 |
| `에디터가 이미지를 서버에 올리지 않고 본문에 박아 넣습니다` | 에디터의 업로드 콜백이 없어 base64 로 들어감 | 사이트 관리자에 문의. 이 상태로는 올리지 않음 |
| `등록을 눌렀지만 목록에서 그 글을 찾지 못했습니다` | 등록 실패(필수값 누락 알림 등) 또는 목록이 다른 탭 | 스크린샷·`브라우저 알림:` 문구 확인 |
| `plan.json 의 ALT가 비어 있습니다` | 2단계 누락 | ALT 채우고 재실행 |

## 비밀번호에 기호가 있을 때

환경변수 입력칸은 `.env` 형식이라 `#` 뒤를 주석으로 버리고, 입력 경로에 따라 다른 기호도
사라집니다. 그래서 로그인이 조용히 실패할 수 있습니다. 이럴 때는 값을 Base64 로 넣습니다 —
`_B64` 가 붙은 이름이 있으면 자동화가 그쪽을 먼저 읽습니다.

```
BOARD_PASSWORD_ZEROCLINIC1_B64=<비밀번호를 Base64 로 바꾼 값>
```

```bash
python3 -c "import base64;print(base64.b64encode('비밀번호'.encode()).decode())"
```

## 하지 말아야 할 것

- 조건을 완화하거나 원고를 임의로 고쳐 올리지 마세요. 수정은 노션에서 합니다.
- 스크립트를 우회해 브라우저를 직접 조작해 글을 올리지 마세요. 노션 되돌려 쓰기와
  로그가 빠지고, 다음 회차에 같은 글이 또 올라갈 수 있습니다.
- 등록된 글을 자동으로 수정·삭제하지 않습니다. 잘못 올라갔으면 사람이 관리자에서 지웁니다.
