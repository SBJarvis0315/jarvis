# 노션→워드프레스 콘텐츠 자동화 구축 가이드

Oct 26, 2026 · @sunwoo

## 0. 이 문서를 읽는 법

이 문서 하나만 있으면 리드젠랩의 콘텐츠 자동화를 처음부터 똑같이 다시 만들 수 있습니다. 사람이 읽어도 되고, AI(클로드 같은 인공지능 비서)에게 통째로 주고 "이대로 만들어 줘"라고 해도 됩니다. 마지막 13장에 AI에게 그대로 복사해 줄 지시문이 있습니다.

**한 문단 요약.** 노션(팀이 쓰는 온라인 메모·표 도구)에 고객사별 "플래너" 표가 있습니다. 매일 정해진 시간에 AI가 그 표를 읽어 원고를 쓰고, 썸네일(글 대표 이미지)을 만들고, 팀이 검수를 끝낸 글을 고객사 홈페이지(워드프레스 또는 자체 게시판)에 올린 뒤, 결과를 다시 노션에 적습니다. 사람은 노션에서 키워드를 넣고 검수만 하면 됩니다.

**어려운 말 풀이.** 본문에서 처음 나올 때마다 다시 풀어 쓰지만, 자주 나오는 것만 모아 둡니다.

| 말 | 뜻 |
| --- | --- |
| 노션 DB(데이터베이스) | 노션 안의 표. 행 하나가 글 한 편, 열 하나가 속성(제목·상태·키워드 같은 칸) |
| 플래너 | 고객사마다 하나씩 있는 노션 DB. 글 한 편의 기획부터 발행까지 모두 여기 적힘 |
| 루틴(예약 작업) | 매일 정해진 시각에 AI가 자동으로 실행하는 작업. 클로드 코드의 "scheduled task" 기능 |
| 저장소(리포지토리) | 코드와 설정 파일을 모아 둔 폴더. 깃허브(GitHub)에 올려 두고 루틴이 매번 받아 씀 |
| 환경변수 | 비밀번호·토큰처럼 코드에 적으면 안 되는 값을 실행 환경에 따로 넣어 두는 칸 |
| REST API | 프로그램이 워드프레스·노션에 글을 올리거나 읽을 때 쓰는 공식 창구 |
| 워드프레스 앱 비밀번호 | 로그인 비밀번호와 별개로, 프로그램 전용으로 발급하는 긴 비밀번호 |
| 슬러그 | 글 주소 끝에 붙는 영문 이름 (예: `/melasma-laser-sessions`) |
| 메타타이틀·메타디스크립션 | 검색 결과에 보이는 제목과 설명문 |
| Rank Math | 워드프레스의 검색엔진 최적화(SEO) 플러그인. 메타타이틀·설명·스키마를 여기 넣음 |
| 스키마 | 검색엔진에게 "이 글은 블로그 글이고 FAQ가 있다"고 알려 주는 숨은 표식 |
| 숏폼·롱폼·엔티티 | 글 유형. 숏폼은 개념 하나를 짧게, 롱폼은 길게, 엔티티는 브랜드·제품 소개 글 |
| 컨펌 진행 중·게재완료 | 플래너의 "진행 상황" 값. 검수 대기와 발행 완료를 뜻함 |

## 1. 전체 그림

> (노션 문서의 흐름 그림을 글로 옮김) 15:00 원고 생성 → 17:00 썸네일 생성 → 사람 검수(컨펌 진행 중) → 고객사 사이트 종류에 따라 09:00·19:00 워드프레스 발행 또는 09:20·19:20 게시판 발행 → 20:00 색인 요청. 모든 단계는 노션 플래너 한 표만 읽고 쓴다.

자동화는 하루에 다섯 번 돌고, 사람이 손대는 곳은 "검수" 한 군데뿐입니다. 모든 단계가 노션 플래너라는 표 하나를 읽고 씁니다.

&#91;embedded content: 하루 흐름 · 자동 5단계, 사람 검수 1단계\]

위 그림에서 원고 생성과 썸네일 생성은 노션만 건드립니다. 발행 두 가지는 고객사 홈페이지에 글을 올린 뒤 플래너에 결과(게재완료, 글 주소)를 되돌려 적습니다. 색인 요청은 발행된 주소를 구글 서치콘솔에 등록해 달라고 요청하는 단계입니다.

**사람이 하는 일은 셋입니다.**

1. 플래너에 행을 만들고 유형(숏폼·롱폼·엔티티)을 고릅니다. 숏폼은 키워드도 AI가 채우지만, 롱폼과 엔티티는 사람이 키워드를 적어야 원고가 생성됩니다.
2. 생성된 원고와 썸네일을 보고, 괜찮으면 발행 예정일을 적고 진행 상황을 "컨펌 진행 중"으로 둡니다. 메타타이틀·메타디스크립션·슬러그는 AI가 채워 두므로 확인만 합니다.
3. 발행 뒤 글이 올바른지 가끔 확인합니다. 실패한 행은 "발행 오류"로 바뀌고 실행 로그에 이유가 남으니 그걸 보고 고칩니다.

**각 단계가 돌아가는 곳.**

| 단계 | 시각(한국) | 무엇이 실행하나 | 코드가 있나 |
| --- | --- | --- | --- |
| 원고 생성 | 15:00 | 클로드 코드 루틴 + 노션 연결(MCP) | 아니요. 긴 지시문(프롬프트)만으로 동작 |
| 썸네일 생성 | 17:00 | 클로드 코드 루틴 → 저장소의 파이썬 코드 | 예 |
| 워드프레스 발행 | 09:00, 19:00 | 클로드 코드 루틴 → 저장소의 파이썬 코드 | 예 |
| 게시판 발행 | 09:20, 19:20 | 클로드 코드 루틴 → 저장소의 파이썬 코드 + 브라우저 | 예 |
| 색인 요청 | 20:00 | 담당자 PC의 AI 브라우저(aside)가 서치콘솔 조작 | 아니요. 지시문만 |

"루틴"은 클로드 코드(Claude Code)의 예약 작업 기능입니다. 정해진 시각에 저장소를 새로 받은 깨끗한 작업 환경을 열고, 적어 둔 지시문을 AI에게 건넵니다. AI는 그 지시문대로 코드를 실행하거나 노션을 직접 읽고 씁니다.

## 2. 준비물

계정 여섯 개와 도구 하나가 필요합니다. 전부 무료로 시작할 수 있고, 유료가 필요한 것은 클로드(Claude) 구독뿐입니다.

| 준비물 | 어디서 만드나 | 무엇에 쓰나 | 꼭 필요한가 |
| --- | --- | --- | --- |
| 노션 워크스페이스 + 내부 통합 | notion.so → 설정 → 연결 → 내부 통합 만들기 | 플래너·설정표·로그를 프로그램이 읽고 쓰는 열쇠(토큰) | 필수 |
| 클로드 코드(Claude Code) 클라우드 환경 | claude.ai/code → 환경(Environment) 만들기 | 루틴이 도는 컴퓨터. 비밀값과 허용 도메인을 여기 등록 | 필수 |
| 깃허브(GitHub) 저장소 | github.com → 새 저장소 | 코드·설정 파일 보관. 루틴이 매번 여기서 최신 코드를 받음 | 필수 |
| 워드프레스 관리자 계정 (고객사마다) | 고객사에게 발급 요청 | 글 올리기. 앱 비밀번호를 따로 발급 | 워드프레스 고객사만 |
| 자체 게시판 관리자 계정 (고객사마다) | 고객사 홈페이지 제작사에게 요청 | 브라우저로 로그인해 글 등록 | 자체 게시판 고객사만 |
| 유튜브 데이터 API 키 | console.cloud.google.com → API 및 서비스 → YouTube Data API v3 | 고객사 채널 영상 목록을 가져와 글에 끼움 | 선택. 없으면 최신 15개만 |
| 구글 서치콘솔 접근 권한 | 고객사 서치콘솔에 담당자 계정 추가 | 발행된 글의 색인 요청 | 선택 |

**노션 내부 통합이란.** 노션에 "프로그램용 계정"을 하나 만드는 것입니다. 만들면 긴 글자열(토큰)이 나오는데, 이게 비밀번호 역할을 합니다. 통합을 만든 뒤에는 **읽고 쓸 모든 DB와 페이지에 그 통합을 연결**해야 합니다. 각 DB 우측 상단 ⋯ → 연결 → 통합 이름 선택. 이걸 빠뜨리면 "권한 없음" 또는 "404" 오류가 납니다. 새 고객사 플래너를 만들 때마다 잊기 쉬운 단계입니다.

**클로드 코드 클라우드 환경이란.** 클로드가 코드를 실행할 수 있는 가상 컴퓨터입니다. 여기에 세 가지를 등록합니다.

1. 환경변수(비밀값). 6장의 목록대로 넣습니다.
2. 네트워크 허용 목록. 이 컴퓨터가 접속해도 되는 사이트 목록입니다. 노션 API, 깃허브, 유튜브, 각 고객사 홈페이지 주소를 넣어야 합니다. 빠지면 "접속 거부" 오류로 발행이 실패합니다.
3. 노션 연결(커넥터). 15:00 원고 생성 루틴은 코드가 아니라 클로드가 노션을 직접 읽고 쓰므로, 루틴에 노션 연결을 붙여 둡니다.

**지금 운영 중인 값.** 환경 이름은 Default 하나이고, 저장소는 `SBJarvis0315/jarvis`, 작업 폴더는 그 안의 `notion-wp-publish/` 입니다. 네트워크 허용 목록에 들어가야 하는 주소는 다음과 같습니다.

- `api.notion.com` (노션)
- `github.com` (저장소)
- `*.youtube.com`, `*.googleapis.com` (유튜브 영상 목록)
- `code.jquery.com` (자체 게시판 편집기가 쓰는 라이브러리)
- 각 고객사 홈페이지 주소 (예: `blog.cleartone.co.kr`, `www.zeroclinic1.com`)
- 외부 권위 출처 사이트(학회·정부기관)는 원고 생성 루틴이 웹 검색 도구로 열므로 따로 넣지 않아도 됩니다

## 3. 노션 구조

노션에는 페이지 하나(운영센터)와 그 안의 표 둘, 그리고 고객사마다 표 하나와 페이지 둘이 있습니다. 열 이름과 선택 값은 코드와 루틴 지시문이 글자 그대로 찾으므로 **토씨 하나 다르게 만들면 안 됩니다.**

### 3-1. 운영센터 페이지

이름은 "콘텐츠 자동화 운영센터 (Medical)"입니다. 루틴 지시문이 이 페이지와 그 안 표 둘의 ID를 고정값으로 가지고 있습니다. 위에서부터 이런 순서입니다.

1. 안내 콜아웃. 어떤 자동화가 어느 고객사에 적용되는지와 운영 가이드 페이지 모음
2. 표 "고객사 설정표" (3-2)
3. 표 "원고 자동 생성 & 썸네일 & 워드프레스 실행 로그" (3-3)
4. "자동화 적용 고객사" 제목 아래, 고객사마다 콜아웃 하나. 그 안에 "○○ - 원고 생성 지침"과 "○○ - 참고자료" 페이지 두 개 (3-5)
5. 맨 아래 "고객사명(※새 고객사 추가시 복제하여 사용)" 콜아웃. 새 고객사를 붙일 때 복제하는 템플릿 페이지 두 개

### 3-2. 고객사 설정표

고객사 한 곳이 한 행입니다. 새 고객사는 여기 행 하나를 추가하면 끝이고, 저장소를 고칠 일은 없습니다. 원고 생성 루틴과 발행 코드가 모두 이 표를 읽습니다.

| 열 이름 | 종류 | 무엇을 적나 | 예 |
| --- | --- | --- | --- |
| 고객사 | 제목 | 표시 이름. 저장소의 고객사별 파일 이름과 같아야 함 | 클리어톤의원 |
| 상태 | 선택: 활성 / 일시중지 | 활성인 행만 모든 자동화가 처리 | 활성 |
| 플래너 DB ID | 텍스트 | 그 고객사 플래너 표의 32자리 ID. 표 주소를 통째로 붙여도 됨 | 37568fa2… |
| 지침 페이지 ID | 텍스트 | "○○ - 원고 생성 지침" 페이지 ID |  |
| 참고자료 페이지 ID | 텍스트 | "○○ - 참고자료" 페이지 ID |  |
| 대상 유형 | 텍스트 | 원고를 자동 생성·발행할 글 유형, 쉼표로 구분 | 숏폼, 브랜드 엔티티, 제품 엔티티 |
| 워드프레스 주소 | 텍스트 | 발행할 사이트 주소. 자체 게시판 고객사도 같은 칸에 적음. 비우면 원고만 만들고 발행은 안 함 | https://blog.cleartone.co.kr |
| 고객사 유형 | 선택: 일반 / 저단가 | 썸네일 대상 범위. 일반은 숏폼만, 저단가는 대상 유형 전부 | 일반 |
| 유튜브 채널 | 텍스트 | 고객사 채널 주소. 비우면 영상을 넣지 않음 | https://www.youtube.com/@CleartoneClinic |
| 회당 최대 처리 건수 | 숫자 | 원고 생성 한 회차에 만들 최대 편수. 상한이지 목표가 아님 | 20 |
| 비고 | 텍스트 | 사람이 읽는 메모 |  |

워드프레스인지 자체 게시판인지는 사람이 고르지 않습니다. 저장소에 그 사이트의 게시판 프로파일(8장)이 있으면 게시판, 없으면 워드프레스로 알아서 갈립니다.

### 3-3. 실행 로그 표

모든 루틴이 돌 때마다 고객사별로 한 줄씩 남깁니다. 문제가 생기면 가장 먼저 여는 표입니다.

| 열 이름 | 종류 | 값 |
| --- | --- | --- |
| 실행 | 제목 | "2026-10-22 09:21 고객사명" 형식 |
| 실행일시 | 날짜 | 한국 시간 |
| 고객사 | 텍스트 |  |
| 단계 | 선택 | 원고 생성 / 썸네일 생성 / 워드프레스 발행 / 게시판 발행 |
| 결과 | 선택 | 성공 / 부분 성공 / 실패 / 대상 없음 |
| 처리 건수 | 숫자 | 실제로 만들거나 발행한 편수 |
| 상세 | 텍스트 | 무엇을 했고 무엇이 왜 빠졌는지. 사람이 할 일이 여기 적힘 |
| 소요 시간(분), 사용 토큰, 비용(USD) | 숫자 | 원고 생성 루틴이 채움. 나머지는 비워 둠 |

"대상 없음"이 하루에 여러 번 찍히는 것은 정상입니다. 검수가 끝난 글이 없으면 발행할 게 없습니다.

### 3-4. 고객사별 플래너 표

이름은 "○○ 피드백 플래너"입니다. 글 한 편이 한 행이고, 행을 열면 나오는 페이지 본문에 원고가 들어갑니다. 모든 고객사가 같은 템플릿을 복제해 쓰므로 열 이름이 늘 같습니다.

| 열 이름 | 종류 | 누가 채우나 | 설명 |
| --- | --- | --- | --- |
| 제목 | 제목 | 사람 또는 AI | 템플릿 이름("템플릿"이 들어감)이면 AI가 지어서 덮어씁니다. 사람이 지은 제목은 그대로 쓰고 고치지 않습니다 |
| 진행 상황 | 상태 | 사람 + 자동 | 시작 전 → (AI가 원고를 넣으면) 컨펌 진행 중 → (발행되면) 게재완료. 실패하면 발행 오류 |
| 유형 | 선택 | 사람 | 숏폼 / 롱폼 / 브랜드 엔티티 / 제품 엔티티 / 네이버 등. 설정표의 대상 유형에 든 것만 자동 처리 |
| 키워드 | 텍스트 | 사람(롱폼·엔티티) / AI(숏폼) | 쉼표 구분, 첫 번째가 메인 키워드. 비어 있으면 원고를 안 만듭니다 |
| 발행 예정일 | 날짜 | 사람 | 이 날짜가 오늘 이하여야 발행. 비어 있으면 발행 안 함 |
| 썸네일 | 파일 | 17:00 루틴 또는 사람 | 대표 이미지. 숏폼은 본문 맨 위에도 같은 그림이 들어감 |
| 본문 이미지 | 파일 | 사람 | 롱폼·엔티티는 필수. 숏폼은 비워 둠 |
| 메타타이틀, 메타디스크립션, 슬러그 | 텍스트 | AI (비어 있을 때만) | 검색 노출용 제목·설명·영문 주소. 사람이 먼저 적으면 그 값이 우선 |
| 카테고리 | 선택 | AI 또는 사람 | 워드프레스에 **이미 있는 분류 이름 그대로** 옵션을 만들어 둠. 이름이 다르면 발행 오류 |
| 게시판 | 선택 | AI 또는 사람 | 개발사가 만든 별도 글 종류(용어사전·백과사전)에 올릴 때만 씀. 없으면 비움 |
| URL | 주소 | 발행 코드 | 발행된 글 주소. "관련 글" 링크의 근거가 되므로 손으로 올린 글도 채워 두면 좋음 |
| 색인 요청 | 선택 | AI(대기) → 20:00 루틴(완료) | 대기 / 완료 / 오류 / 개수 제한 |
| 담당자, 마감일, 작업년월, 고객사 공유용 URL | 각종 | 사람 | 팀 관리용. 자동화는 읽지 않음 |

"진행 상황"에는 반드시 시작 전, 컨펌 진행 중, 게재완료, 발행 오류 네 값이 있어야 합니다. 그 밖의 값(기획완료, 작성중 등)은 팀이 자유롭게 쓰고 자동화는 건드리지 않습니다.

**행 페이지(글 한 편)의 본문 구조.** 위에서부터 이 순서로 들어 있고, 발행 코드는 이 구조를 믿고 본문을 잘라냅니다.

| 위치 | 내용 | 발행되나 |
| --- | --- | --- |
| 회색 안내 콜아웃 | 팀 안내문 | 아니요 |
| "콘텐츠 가이드" 토글 | 담당 매니저가 적는 기획안. AI가 원고를 쓸 때 읽음 | 아니요 |
| 구분선 아래 AI가 붙인 원고 | "**메타 디스크립션**" 라벨 + 문단, `# H1`, `## H2`부터 클로징까지 | **`## H2`부터 클로징까지만** |
| 구분선 뒤 검수용 섹션 | 📋 작성 메타 정보, ✅ 셀프 점검 결과, ⚠️ 사용자 확인 요청 | 아니요 |

### 3-5. 고객사별 지침 페이지와 참고자료 페이지

**원고 생성 지침** 페이지는 AI가 원고를 쓸 때 따르는 규칙서입니다. 템플릿은 0장부터 9장까지 있습니다.

| 장 | 내용 |
| --- | --- |
| 역할, 0. 불변 규칙 | 법적 리스크 최우선, 추측 금지, 질문하지 않고 「확인 필요」로 표시 |
| 1. 입력 | 플래너 행에서 오는 것, 참고자료에서 오는 것, 충돌 시 우선순위 |
| 2. 유형 확인 | 유형에 맞는 절만 따른다 |
| 3. 유형별 작성 규칙 | 롱폼·숏폼·브랜드 엔티티·제품 엔티티의 분량·골격·말투 |
| 4. 공통 작성 규칙 | 헤딩(H3 하드룰), 문장(한 단락 1\~2문장, 이모지 제한), 하이퍼링크, 외부 출처 검증 |
| 5. 메타 필드와 분류 | 메타타이틀·메타디스크립션·슬러그 규칙, 카테고리·게시판 고르기 |
| 6. 법적 리스크 필터 | 공통 카드 + 업종 카드(화장품·의료기관·건강기능식품) |
| 7. AI 티 제거 | 점검 질문 |
| 8. 출력 형식 | **절대 고치면 안 되는 장.** 발행 코드가 이 골격을 믿고 본문을 자릅니다 |
| 9. 발행 전 자가 점검 | 체크리스트 |

**참고자료** 페이지에는 담당 매니저가 직접 넣습니다. 콘텐츠 작성 가이드라인, 브랜드·제품·타겟 정의, 브랜드 엔티티, 제품 엔티티, 표기 규칙표, 금지 표현, 수치 자료, 외부 권위 출처 주소표(기관명 → 공식 URL). 모두 **텍스트로** 넣어야 합니다. PDF 같은 파일 첨부는 AI가 읽지 못합니다.

두 페이지 모두 상단 안내 콜아웃에 "복제 후 고객사에 맞게 고치고 이 콜아웃은 지우세요"라는 설명이 들어 있습니다.

## 4. 워드프레스 쪽 준비

워드프레스 고객사마다 세 가지를 합니다. 앱 비밀번호 발급, 브리지 플러그인 설치, 분류 이름 맞추기입니다.

### 4-1. 앱 비밀번호 발급

워드프레스 관리자 → 사용자 → 프로필 → "응용 프로그램 비밀번호"에서 새로 만듭니다. 로그인 비밀번호가 아니라, 프로그램만 쓰는 별도 비밀번호입니다. 띄어쓰기가 섮인 형태로 나오는데 그대로 써도 됩니다. 사용자는 글을 올릴 수 있는 권한(편집자 이상)이어야 합니다.

발행 계정이 우리 작업 계정(표시 이름에 Growth가 들어감)이면, 글 작성자는 자동으로 다른 사용자로 바뀝니다. Growth 아닌 사용자 중 번호가 가장 작은 계정을 고르고, 직접 정하고 싶으면 저장소의 작성자 파일(5장)에 적습니다. 저자 이름은 검색엔진이 신뢰도 신호로 읽기 때문입니다.

### 4-2. 브리지 플러그인 설치

저장소의 `wp-mu-plugin/notion-publish-bridge-1.2.0.zip` 파일을 워드프레스 관리자 → 플러그인 → 새로 추가 → 플러그인 업로드로 올리고 활성화합니다. 이름은 "Notion Publish Bridge"입니다.

**왜 필요한가.** 워드프레스의 공식 창구(REST API)는 등록되지 않은 추가 정보를 오류 없이 조용히 버립니다. Rank Math가 쓰는 검색 제목·설명·스키마가 바로 그 "추가 정보"입니다. 이 플러그인이 없으면 글은 올라가는데 검색 설정만 혅 비게 됩니다.

플러그인이 하는 일:

- Rank Math 항목(제목·설명·포커스 키워드·정규 주소)을 창구에 등록해 받게 함
- 글에 노션 페이지 ID를 각인해 중복 발행을 막음. 주소 `/wp-json/notion-bridge/v1/lookup`로 "이 노션 페이지가 이미 올라갔나" 확인
- `/seo/글번호`로 검색 설정과 스키마(BlogPosting, FAQPage)를 한 번에 기입. 기본으로 붙는 Article 스키마는 비움
- `/ping`으로 플러그인 버전과 사이트의 글 종류 목록을 알려 줌
- 서버가 로그인 정보(Authorization 헤더)를 중간에 지우는 호스팅이면, 보조 헤더 `X-Notion-Authorization`에서 로그인 정보를 복원함 (쉬즈메디병원에서 실제로 있었던 일). `/auth-probe`로 이 상태를 점검할 수 있음

설치 확인은 브라우저에서 `https://고객사주소/wp-json/notion-bridge/v1/ping`을 열어 `"ok":true`가 나오면 됩니다.

**플러그인을 못 깔 때.** 서버 방화벽이 플러그인 설치를 막는 고객사도 있습니다. 그래도 발행은 멈추지 않고 "제한 모드"로 동작합니다. 글·이미지·분류·주소 기입은 되고, 중복 확인은 슬러그로 하며, Rank Math 설정만 빠집니다. 이때는 사람이 워드프레스에서 검색 설정을 채워야 하고, 발행 보고에 그 사실이 따로 적힙니다.

### 4-3. 분류 이름 맞추기

플래너의 "카테고리" 선택 옵션을 워드프레스에 이미 있는 분류 이름과 글자 그대로 맞춥니다. 중간에 바꿔 주는 대응표는 없습니다. 이름이 다르면 발행을 멈추고 실제 분류 목록을 오류 메시지에 보여 줍니다. 없는 이름으로 분류를 새로 만들지 않습니다. 오타 하나로 유령 분류가 생기던 일을 막기 위해서입니다.

### 4-4. 개발사가 별도 글 종류를 만든 사이트

메뉴는 일반 분류처럼 보이지만 속은 "용어사전", "백과사전" 같은 별도 글 종류인 사이트가 있습니다(비컴성형외과, 쉬즈메디병원). 일반 글로 올리면 그 섹션에 안 들어갑니다. 발행 코드는 플래너의 "카테고리" 이름이 일반 분류에 없으면 사이트에 어떤 글 종류가 있는지 물어보고, 그 분류를 가진 글 종류로 알아서 찾아갑니다. 같은 분류 이름이 여러 글 종류에 있어 기계가 고를 수 없을 때만 저장소의 글 종류 파일(5장)에 적어 줍니다.

## 5. 저장소(코드) 구조

저장소 안에는 폴더가 셋 있습니다. 발행 코드, 클로드가 읽는 작업 설명서, 루틴 지시문 보관함입니다. 언어는 파이썬이고, 외부 라이브러리는 넷(requests, Pillow, pillow-heif, playwright)입니다.

```
jarvis/
├── notion-wp-publish/          발행 코드와 고객사별 설정 파일
├── .claude/skills/             클로드가 읽는 작업 설명서(스킬) 3개
│   ├── wp-publish/SKILL.md     워드프레스 발행 절차
│   ├── board-publish/SKILL.md  자체 게시판 발행 절차
│   └── wp-thumbnail/SKILL.md   썸네일 생성 절차
└── routines/                   루틴 지시문 원문 보관 (루틴 화면에는 이력이 없어서)
```

**스킬이란.** 클로드가 "발행해 줘" 같은 요청을 받았을 때 따르는 절차서입니다. 루틴 지시문은 "스킬에 적힌 대로 해라"고만 말하고, 세부 절차는 스킬 파일에 있습니다. 그래서 절차를 바꿀 때 루틴을 건드리지 않고 스킬 파일만 고칩니다.

### 5-1. 발행 코드 폴더

```
notion-wp-publish/
├── README.md               설치·동작 규칙 전체 설명
├── requirements.txt        필요한 라이브러리 목록
├── config/defaults.json    전 고객사 공통값 (열 이름, 상태 이름, 표 ID)
├── src/notionwp/           파이썬 코드
├── tests/                  자동 테스트 414개 (네트워크 없이 돌아감)
├── wp-mu-plugin/           워드프레스에 올리는 브리지 플러그인 (zip 포함)
├── assets/fonts/           썸네일 서체 (NotoSansKR, NataSans, WantedSans)
├── designs/                고객사별 썸네일 디자인 + logos/ 로고
├── boards/                 자체 게시판 사이트 프로파일 (호스트별)
├── posttypes/              별도 글 종류 대응표 (필요한 고객사만)
├── links/                  글 끝 "참고 자료·관련 글" 링크 규칙 (필요한 고객사만)
├── tails/                  글 맨 끝 고정 블록 (필요한 고객사만)
├── authors/                글 작성자 지정 (필요한 고객사만)
└── certs/                  고객사 서버가 빠뜨린 중간 인증서 (필요한 경우만)
```

고객사별 설정 파일은 **모두 선택**입니다. 파일이 없는 고객사는 기본 동작으로 갑니다. 파일 이름은 설정표의 고객사 이름과 같아야 합니다(예: `designs/클리어톤의원.json`). 설정표에 칸을 늘리지 않으려고 저장소에 둡니다.

### 5-2. 코드 파일별 역할

| 파일 | 하는 일 |
| --- | --- |
| `__main__.py` | 명령줄 입구. `--dry-run`, `--prepare`, `--plan`, `--draft`, `--thumbnails`, `--board`, `--board-inspect`, `--client`, `--skip` 옵션 |
| `config.py` | 공통 설정과 비밀값 읽기. 사이트 주소에서 환경변수 이름 키를 뽑음 |
| `registry.py` | 노션 고객사 설정표를 읽어 고객사 목록을 만듦 |
| `notion_api.py` | 노션 읽기·쓰기 |
| `publish.py` | 발행 조건 검사와 전체 진행. 가장 중요한 파일 |
| `extract.py` | 원고 페이지에서 발행할 본문만 골라냄 |
| `gutenberg.py` | 노션 블록을 워드프레스 편집기(구텐베르크) 형식으로 바꿈 |

| `images.py` | 이미지 배치 계산, 크기 축소, HEIC 변환 |
| `plan.py` | 준비 단계 산출물 `plan.json` 읽기·쓰기 |

| `schema.py` | BlogPosting, FAQPage 스키마 생성 |
| `wordpress.py` | 워드프레스 창구 호출, 글 종류 탐색, 이미지 업로드 |
| `links.py`, `tail.py`, `posttype.py`, `authors.py` | 고객사별 설정 파일 적용 |
| `runlog.py` | 실행 로그 표에 한 줄 남김 |
| `thumbnail.py`, `thumbnails.py`, `designs.py`, `brand.py` | 썸네일 그리기 |
| `board.py`, `boardhtml.py`, `board_publish.py` | 자체 게시판 발행 |
| `trust.py` | 고객사 서버 인증서 보완 |

### 5-3. 고객사별 설정 파일 형식

모두 JSON(중괄호로 값을 적는 텍스트 형식)이고, `note` 칸에 "왜 이렇게 정했는지"를 사람 말로 적어 둡니다.

**별도 글 종류** `posttypes/비컴성형외과.json`

```json
{
  "client": "비컴성형외과",
  "boards": {
    "용어사전": { "rest_base": "glossary", "taxonomy_rest_base": "glossary_cat" }
  }
}
```

플래너의 "게시판" 값이 용어사전이면 glossary라는 글 종류로 올리고, 분류는 glossary\_cat에서 찾습니다. 쉬즈메디병원은 "백과사전" → encyclopedia / encyclopedia\_cat입니다.

**글 끝 링크** `links/참포도나무병원.json`

```json
{
  "client": "참포도나무병원",
  "related": true,
  "references": {
    "대한신경외과학회": "https://www.neurosurgery.or.kr/",
    "질병관리청 국가건강정보포털": "https://health.kdca.go.kr/healthinfo/"
  }
}
```

원고 끝 "참고 자료:" 줄의 기관명에 이 표의 주소를 걸고, "관련 글:" 줄의 제목은 그 고객사 플래너의 게재완료 행과 맞춰 그 행의 URL을 겁니다. 표에 없는 기관은 글자만 남기고, 플래너에 없는 글은 항목을 븼니다. 주소를 지어내지 않습니다.

**글 맨 끝 고정 블록** `tails/참포도나무병원.json`

```json
{
  "client": "참포도나무병원",
  "types": ["숏폼"],
  "blocks": "<!-- wp:block {\"ref\":2246} /-->"
}
```

워드프레스에 만들어 둔 "패턴"(의료진 프로필 등)을 숏폼 글 맨 아래에 붙입니다. 패턴 번호는 워드프레스 편집 화면의 코드 보기에서 복사합니다.

**글 작성자** `authors/지혜로운 필라테스.json`

```json
{ "client": "지혜로운 필라테스", "author": "이지혜" }
```

워드프레스 사용자의 표시 이름, 사용자명, 번호 중 무엇이든 됩니다.

**썸네일 디자인**과 **게시판 프로파일**은 9장과 8장에서 따로 설명합니다.

### 5-4. 공통 설정 `config/defaults.json`

여기에는 전 고객사 공통값만 있습니다. 고객사 고유값은 하나도 없습니다.

- 설정표 DB ID와 열 이름
- 플래너 열 이름 대응(코드 안 이름 → 노션 열 이름)
- 상태 이름 세 개: 컨펌 진행 중 / 게재완료 / 발행 오류
- 실행 로그 DB ID
- 렌더링: H2 앞 여백 20px, 표 가운데 정렬, 숏폼은 썸네일을 본문 맨 위에도 넣음(`hero_image_types`)

새로 구축할 때는 설정표와 로그 DB의 ID 두 개만 자기 노션 값으로 바꾸면 됩니다.

## 6. 비밀값(환경변수)

비밀번호와 토큰은 코드나 노션에 절대 적지 않고, 클로드 코드 환경의 환경변수 칸에만 넣습니다. 루틴이 돌 때 그 값을 자동으로 읽습니다.

| 이름 | 값 | 필수 |
| --- | --- | --- |
| `NOTION_TOKEN` | 노션 내부 통합 토큰 (ntn\_ 또는 secret\_ 로 시작) | 필수 |
| `WP_USER_<키>` | 그 고객사 워드프레스 사용자명 | 워드프레스 고객사마다 |
| `WP_APP_PASSWORD_<키>` | 그 고객사 워드프레스 앱 비밀번호 | 워드프레스 고객사마다 |
| `BOARD_USER_<키>` | 자체 게시판 관리자 아이디 | 자체 게시판 고객사마다 |
| `BOARD_PASSWORD_<키>` 또는 `BOARD_PASSWORD_<키>_B64` | 자체 게시판 관리자 비밀번호. 기호(#, @)가 들어 있으면 Base64로 바꿔 `_B64` 이름에 | 자체 게시판 고객사마다 |
| `YOUTUBE_API_KEY` | 유튜브 데이터 API 키 (전 고객사 공통) | 선택 |
| `WP_USER`, `WP_APP_PASSWORD` | 고객사별 값이 없을 때 쓰는 공용 계정 | 선택 |

**키 만드는 규칙.** 설정표의 사이트 주소에서 도메인 이름만 남기고 대문자로 바꿉니다. 사람이 정하는 게 아니라 코드가 주소에서 자동으로 뽑으므로, 아래 규칙을 따라야 코드가 찾습니다.

| 설정표의 주소 | 키 | 환경변수 이름 |
| --- | --- | --- |
| https://blog.cleartone.co.kr | CLEARTONE | WP\_USER\_CLEARTONE, WP\_APP\_PASSWORD\_CLEARTONE |
| https://www.champodonamu.com/blog/ | CHAMPODONAMU | WP\_USER\_CHAMPODONAMU, WP\_APP\_PASSWORD\_CHAMPODONAMU |
| https://peakpilateskr.com/ | PEAKPILATESKR | WP\_USER\_PEAKPILATESKR, WP\_APP\_PASSWORD\_PEAKPILATESKR |
| https://www.zeroclinic1.com | ZEROCLINIC1 | BOARD\_USER\_ZEROCLINIC1, BOARD\_PASSWORD\_ZEROCLINIC1\_B64 |

규칙: `www.`와 끝의 `.com`, `.co.kr` 같은 꼬리를 떼고, 남은 것을 대문자로, 점은 밑줄로 바꿉니다. `blog.cleartone.co.kr`처럼 앞에 붙은 이름이 있으면 도메인 본체만 남습니다. 코드가 계정을 못 찾으면 어떤 이름으로 넣어야 하는지 오류 메시지에 그대로 알려 줍니다.

**안전 규칙 세 가지.**

1. 비밀값은 환경변수에만. 노션 페이지, 저장소 파일, 루틴 지시문 어디에도 적지 않습니다.
2. 아이디만 넣고 비밀번호를 빠뜨리면 코드가 일부러 멈춥니다. 반쪽만 있으면 엉뚱한 계정으로 로그인할 수 있어서입니다.
3. 비밀번호에 `#`이 들어 있으면 환경변수 입력칸이 그 뒤를 주석으로 보고 잘라 버립니다. 그럴 때는 Base64(글자를 영문·숫자로만 된 다른 글자열로 바꾸는 방식)로 바꿔 `_B64` 이름에 넣습니다. 바꾸는 명령: `python3 -c "import base64;print(base64.b64encode('비밀번호'.encode()).decode())"`

**환경변수는 세션이 시작할 때 고정됩니다.** 값을 바꾼 뒤에는 이미 열려 있는 클로드 세션은 예전 값을 그대로 가지고 있습니다. 루틴은 매번 새 세션을 열므로 다음 회차부터 새 값을 씁니다.

## 7. 발행 코드가 하는 일

발행은 세 단계입니다. 준비(이미지 내려받기), 검수(클로드가 이미지를 보고 대체 텍스트를 씁니다), 발행. 코드는 이미지를 볼 수 없으므로 가운데 단계만 클로드가 합니다.

```
cd notion-wp-publish
pip install -q -r requirements.txt
PYTHONPATH=src python3 -m notionwp --prepare work/   # 1) 준비
# 2) 클로드가 work/<페이지ID>/plan.json 의 alt 를 채움
PYTHONPATH=src python3 -m notionwp --plan work/      # 3) 공개 발행
```

### 7-1. 발행 조건

아래를 전부 만족해야 발행합니다. 하나라도 빠지면 그 행은 건드리지 않고 사유만 로그에 남깁니다.

- 진행 상황 = 컨펌 진행 중
- 유형이 설정표의 대상 유형 안
- 제목, 발행 예정일(오늘 이하), 페이지 안 원고
- 썸네일, 본문 이미지(숏폼은 면제), 메타타이틀, 메타디스크립션, 슬러그

### 7-2. 본문 자르기

원고 페이지에서 `## H2`부터 클로징까지만 발행합니다. 콘텐츠 가이드 토글, 메타 디스크립션 문단, H1, 구분선 뒤 검수용 섹션은 모두 뻗니다. 그래서 지침 8장 "출력 형식"이 깨지면 본문이 엉뚱한 자리에서 잘립니다.

### 7-3. 워드프레스 형식으로 바꾸기

노션 블록을 구텐베르크(워드프레스 편집기) 블록으로 바꿉니다. H2 앞에 여백 블록을 넣고, 헤딩·표·목록·굵게·링크를 그대로 옮깁니다. 글 끝 "참고 자료"·"관련 글" 줄에 링크를 걸고(links 파일이 있는 고객사), 맨 끝에 고정 블록을 붙입니다(tails 파일이 있는 고객사).

### 7-4. 이미지

썸네일 칸은 대표 이미지, 본문 이미지 칸은 H2 구간에 고르게 나눠 넣습니다. 숏폼은 썸네일 한 장이 대표 이미지이면서 본문 맨 위에도 들어갑니다. 준비 단계가 하는 일:

- 노션 첨부 주소는 1시간 뒤 만료되므로 내려받아 워드프레스에 다시 올립니다
- 파일 이름을 슬러그 기반 영문으로 바꿉니다 (기미레이저1.jpg → melasma-laser-sessions-1.jpg)
- 1.5MB 넘는 사진은 긴 변 1600px로 줄입니다
- 아이폰 HEIC 같은 브라우저가 못 그리는 형식은 JPEG로 바꿉니다. 못 바꾸면 그 글 발행을 멈춥니다
- `plan.json`에 본문 헤딩 구조와 각 구간 발췌를 같이 담습니다. 같은 장비 사진도 어느 구간에 놓이느냐에 따라 대체 텍스트가 달라져야 하기 때문입니다

대체 텍스트(ALT)는 클로드가 이미지를 직접 보고 한국어 20\~50자로 씁니다. 치료 전후 비교나 효과 단정 표현은 의료광고 규정상 쓰지 않습니다. 하나라도 비어 있으면 발행 단계가 거부합니다.

### 7-5. 유튜브 영상

설정표에 채널이 있으면 준비 단계가 영상 목록을 `plan.json`에 담고, 클로드가 원고 주제와 맞는 영상 하나를 고릅니다. 기준은 주제 하나뿐이고, 맞는 게 없으면 비워 둡니다. 채널이 퍼가기를 꺼 둔 영상은 임베드 대신 "▶ 유튜브에서 영상 보기" 링크 한 줄로 들어갑니다. 영상 때문에 발행이 막히지는 않습니다.

### 7-6. 검색 설정과 스키마

| Rank Math 항목 | 출처 |
| --- | --- |
| 검색 제목 | 플래너 메타타이틀 |
| 검색 설명 | 플래너 메타디스크립션 |
| 글 주소 | 플래너 슬러그 |
| 포커스 키워드 | 플래너 키워드 (첫 번째가 메인) |
| 스키마 | 원고에서 자동 생성. BlogPosting은 항상, FAQPage는 `### Q1.` 형식의 FAQ가 있을 때만 |

### 7-7. 순서와 중복 방지

초안 생성 → 노션 페이지 ID 각인 → 검색 설정 기입 → 공개. 중간에 실패하면 초안 상태로 남아 공개되지 않고, 다음 회차가 각인된 ID로 그 초안을 찾아 이어서 진행합니다. 같은 원고가 두 번 나가지 않습니다.

발행이 끝나면 플래너 행을 게재완료로 바꾸고 URL 칸에 글 주소를 적습니다. 실패한 행은 발행 오류로 바꿉니다. 마지막으로 실행 로그에 한 줄을 남깁니다.

## 8. 자체 게시판 발행 (워드프레스가 아닌 홈페이지)

홈페이지 제작사가 만든 관리자 화면에 글을 올리는 고객사(제로클리닉)는 프로그램용 창구가 없습니다. 그래서 브라우저 자동화(Playwright라는 도구로 크롬을 보이지 않게 열어 조작)가 팀원이 손으로 하던 일을 그대로 합니다.

```
로그인 → 게시판 목록 → 글쓰기 → 이미지 업로드 → 코드 보기 칸에 HTML 붙이기 →
조회수·제목 입력 → 등록 → 목록에서 글 번호 확인 → 플래너 게재완료 + URL
```

명령은 워드프레스와 같고 `--board`만 붙입니다. 실행 전에 `pip install -q playwright`가 필요하고, 브라우저는 환경에 설치된 크롬(Chromium)을 씁니다.

**워드프레스와 다른 점.**

|  | 워드프레스 | 자체 게시판 |
| --- | --- | --- |
| 슬러그 | 필수 | 불필요 (글 번호로 주소가 정해짐) |
| 검색 설정·스키마·분류 | 있음 | 없음. 본문 맨 위에 `<title>`과 `<meta description>`을 넣는 팀 관행만 따름 |
| 본문 형식 | 구텐베르크 블록 | 평범한 HTML. 헤딩에 글자 크기·여백 직접 지정, 목록은 `•` 문단, 표는 테두리 직접 지정 |
| 이모지 | 제한 없음 | 세 바이트까지만. 네 바이트 이모지(📚 등)는 게시판 DB가 못 담아 "?"로 바뀜. 코드가 바꿔 줌 |
| 중복 방지 | 글에 노션 ID 각인 | 관리자 목록에서 제목 대조 |
| 임시저장 | 있음 | 없음. `--plan`은 곳바로 공개 |
| 조회수 | 없음 | 500\~1100 사이 임의 값 (팀 관행) |
| 영상 | 있음 | 넣지 않음 |
| 로그 단계 | 워드프레스 발행 | 게시판 발행 |

**사이트 프로파일** `boards/www.zeroclinic1.com.json`. 관리자 화면은 제작사마다 다르므로 생김새를 파일로 굳혀 둡니다.

| 항목 | 뜻 | 제로클리닉 값 |
| --- | --- | --- |
| `admin_url` | 글 목록 화면 주소 | /admin/board/boardseo\_list.php |
| `login_url` | 로그인 화면 | /admin/Login.php |
| `public_url` | 공개 글 주소 틀. {id}에 글 번호 | /htm/boardseo\_read.php?id={id} |
| `write_button`, `submit_buttons` | 글쓰기·등록 버튼 글자 | 글쓰기 |
| `submit_selector` | 그림 버튼일 때 버튼을 집는 선택자 | a\[href\*='checkForm'\] |
| `labels` | 폼의 행 머리글 (제목·조회수·내용·HTML) |  |
| `html_mode_value` | HTML 모드 라디오 값 | Y |
| `hit_min`, `hit_max` | 조회수 범위 | 500, 1100 |

새 사이트는 `--board-inspect work/inspect --client ○○`로 관리자 화면 스크린샷과 폼 구조를 떠서 보고, 제로클리닉 파일을 복사해 고칩니다. 제로클리닉에서 확인한 세부 기록은 `boards/inspect/zeroclinic/NOTES.md`에 있습니다. 예를 들어 같은 이름의 빈 게시판이 따로 있다는 것, 등록 버튼이 글자가 아니라 그림이라는 것, 이 호스팅의 환경변수 칸이 `#` 뒤를 잘라 비밀번호를 Base64로 넣어야 한다는 것입니다.

발행이 실패하면 그 순간의 스크린샷이 `work/board/`에 남습니다. 사이트가 개편되어 자동화가 깨지면 그 그림부터 봅니다.

## 9. 썸네일 자동 생성

플래너에서 제목은 있는데 썸네일 칸이 비어 있는 행을 찾아, 고객사 전용 디자인으로 이미지를 만들어 붙입니다. 워드프레스는 건드리지 않으므로 원고만 만드는 고객사도 처리합니다.

```
PYTHONPATH=src python3 -m notionwp --thumbnails
```

**대상 조건 셋.** 유형이 대상에 든다(일반 고객사는 숏폼만, 저단가 고객사는 대상 유형 전부), 제목이 있고 "템플릿"이 들어 있지 않다, 썸네일 칸이 비어 있다. 이미 붙은 썸네일은 절대 덮어쓰지 않습니다. 다시 만들고 싶으면 사람이 파일을 지우면 됩니다.

**디자인 파일** `designs/<고객사>.json`. 색·서체·로고·치수를 한 번 정해 굳혀 두고 이후 그 파일만 읽습니다. 같은 고객사는 늘 같은 모습이 나옵니다. 실행할 때마다 색을 다시 정하면 썸네일이 조금씩 달라지므로, **이미 있는 디자인 파일은 다시 만들지 않습니다.**

| 항목 | 뜻 |
| --- | --- |
| `skeleton` | 골격. band(진한 바탕 1200×630), minimal(흰 바탕 여백형 1920×1080, 로고 중심), card(1200×628 카드형), journal(1200×900, 여러 비율에서 글자가 살아남는 구성) |
| `width`, `height` | 캔버스 크기 |
| `palette` | 배경, 강조, 제목, 부제, 뱃지 배경·글자, 브랜드, 흡림, 구분선, 장식 색 10개 |
| `latin_font`, `hangul_font` | 영문·한글 서체 (저장소 assets/fonts 안의 것) |
| `name_en`, `domain` | 영문 이름과 도메인. 그림 아래에 찍힘 |
| `logo` | logos/ 폴더의 로고 파일. 없으면 글자 로고로 대신 |
| `layout`, `layout_by_type` | 여백·글자 크기 같은 치수. 유형별로 다르게 둘 수 있음 |
| `variants` | 한 고객사가 여러 모양을 돌아가며 쓸 때 (클리어서울안과: 블루·라이트·네이비). 글마다 순번대로 돌아감 |
| `note` | 무엇을 근거로 이렇게 정했는지 |

제목은 "메인 키워드 | 부연" 형태이므로 그 경계에서 갈라 앞토막을 큰 글씨로 씁니다. 그리는 것은 크롬 브라우저입니다. 글자가 길면 상자에 들어올 때까지 크기를 줄여야 하는데, 브라우저의 글자 배치 기능을 빌리는 편이 정확해서입니다.

**새 고객사 디자인 정하기.** 디자인 파일이 없으면 "확정된 썸네일 디자인이 없습니다" 오류가 나고, 클로드가 스킬 문서의 절차대로 직접 정해 굳힙니다.

1. 로고 이미지와 참고자료 페이지에서 브랜드 색을 정합니다. 홈페이지 HTML에서 색을 기계적으로 뽑으면 카카오톡 버튼 초록 같은 엉뚱한 색이 나오므로 금지입니다.
2. 홈페이지가 썸네일을 어떤 비율로 잘라 보여 주는지 재서 규격을 정합니다. 글자가 잘리지 않는 것이 1순위입니다.
3. 팀이 레퍼런스 이미지를 주면 파일로 받아 픽셀을 재서 치수를 맞춥니다. 눈대중으로 맞추지 않습니다.
4. 한 장 뽑아 눈으로 확인하고 디자인 파일과 로고를 저장소에 커밋합니다.

만든 썸네일은 노션 파일 업로드 창구로 그 행의 썸네일 칸에 붙습니다. 실행 로그에는 단계 "썸네일 생성"으로 남습니다.

## 10. 예약 작업(루틴) 전체

루틴은 claude.ai/code의 예약 작업 화면에서 만듭니다. 각 루틴에는 실행 시각, 환경(Default), 저장소, 그리고 지시문(프롬프트)이 들어갑니다. 지시문 원문은 저장소의 `routines/` 폴더에 보관됩니다. 루틴 화면에는 변경 이력이 없어서, 바꾸기 전 상태를 거기 남겨 두어야 되돌릴 수 있습니다.

| 이름 | 시각(한국) | 지시문 원문 | 노션 연결 필요 |
| --- | --- | --- | --- |
| \[15:00\]노션 피드백 플래너 원고 자동화 v2 (커넥터) | 매일 15:00 | `routines/15-00-원고-자동화-v2.키워드중복보강.txt` | 예 |
| \[17:00\]썸네일 자동 생성 | 매일 17:00 | 짧음. "wp-thumbnail 스킬대로 `--thumbnails` 실행" | 아니요 |
| \[09:00\]워드프레스 자동 발행 | 매일 09:00 | `routines/09-00_19-00-워드프레스-자동-발행.txt` | 아니요 |
| \[19:00\]워드프레스 자동 발행 | 매일 19:00 | 위와 같음 | 아니요 |
| \[09:20\]자체 게시판 자동 발행 | 매일 09:20 | 짧음. "board-publish 스킬대로 `--board` 실행" | 아니요 |
| \[19:20\]자체 게시판 자동 발행 | 매일 19:20 | 위와 같음 | 아니요 |
| 발행 URL 자동 색인 요청 | 매일 20:00 | 클로드 코드가 아니라 담당자 PC의 AI 브라우저(aside)에 있음. 덧붙인 규칙만 `routines/20-00-색인-요청-aside.추가규칙.txt` | 해당 없음 |

**15:00 원고 생성 루틴이 하는 일.** 코드 없이 지시문만으로 동작하므로, 지시문이 곷 설계입니다. 13단계로 되어 있습니다.

1. 설정표를 읽어 활성 고객사만 처리
2. 숏폼 키워드 채우기. 키워드가 빈 숏폼 행에 그 분야의 기본 개념을 하나씩 넣음. **기존 글과 개념이 같으면 말만 바꿔 넣지 않고 버림.** 0건이 정답일 수 있음
3. 대상 행 추출: 시작 전 + 키워드 있음 + 대상 유형
4. 행의 "콘텐츠 가이드" 토글 확인
5. 지침·참고자료 페이지 읽기
6. 유형 확인
7. 키워드 해석 (첫 번째가 메인)
8. 제목 처리 (템플릿 이름이면 지어서 덮어쓰기)
9. 원고 생성. 외부 권위 링크는 웹 검색으로 검증, 관련 글은 플래너 게재완료 행에서만, 이미지는 다루지 않음
10. 행 페이지 끝에 원고 추가 (기존 내용 삭제 금지)
11. 진행 상황을 컨펌 진행 중으로
12. 메타타이틀·메타디스크립션·슬러그·카테고리·색인 요청(대기) 기입. 비어 있을 때만
13. 실행 로그 기록

지시문에는 절대 금지 목록도 있습니다. 다른 행 수정 금지, 선택 옵션 새로 만들기 금지(표 구조가 바뀜), 토큰을 아끼려고 지침을 대충 읽지 않기.

**루틴 두 종류.** 클로드 코드 안에서 만든 루틴(발행·썸네일·게시판)은 클로드가 대화 중에 지시문을 고칠 수 있습니다. 반면 15:00 원고 생성 루틴은 다른 경로로 만들어져 클로드가 고칠 수 없고, 사람이 저장소 파일 내용을 복사해 붙여 넣어야 합니다. 새로 구축할 때는 모두 클로드 코드 안에서 만드는 편이 낫습니다.

**발행 루틴 지시문의 핵심.** 스킬 문서를 따르라, 먼저 `pip install -q -r requirements.txt`, 준비 → 이미지를 직접 보고 ALT 작성 → 발행, 결과 보고. 브리지 플러그인이 없어 제한 모드로 발행된 고객사는 반드시 따로 적을 것. 발행 조건을 임의로 완화하지 말 것. 로그 행을 직접 만들지 말 것(코드가 남김).

**색인 요청 루틴의 규칙.** 플래너에서 색인 요청 = 대기인 행의 URL을 구글 서치콘솔에서 검사하고 색인 생성을 요청한 뒤 완료로 바꿉니다. 이미 요청 기록이 보이면 다시 요청하지 않고 완료로만 바꿉니다. 대기 → 완료 한 방향만 허용합니다.

## 11. 새 고객사 추가 절차

순서대로 하면 됩니다. 저장소를 고치는 단계는 마지막 두 개뿐이고, 그마저 클로드가 알아서 합니다.

- [ ] 노션 운영센터에서 "고객사명(※새 고객사 추가시 복제하여 사용)" 콜아웃을 복제해 고객사 이름으로 바꾼다
- [ ] 복제된 "○○ - 원고 생성 지침"에서 고객사명, 글자 수, 업종 카드를 고치고 상단 안내 콜아웃을 지운다. 8장 출력 형식은 손대지 않는다
- [ ] "○○ - 참고자료"에 콘텐츠 가이드라인, 브랜드·제품·타겟 정의, 표기 규칙, 금지 표현, 외부 출처 주소표를 텍스트로 넣는다
- [ ] 플래너 DB를 기존 고객사 플래너에서 복제해 만든다. 열 이름과 진행 상황 값(시작 전·컨펌 진행 중·게재완료·발행 오류)이 그대로여야 한다
- [ ] 플래너의 "카테고리" 옵션을 워드프레스 분류 이름과 글자 그대로 만든다
- [ ] **플래너 DB, 지침 페이지, 참고자료 페이지에 노션 통합을 연결한다** (⋯ → 연결). 이걸 빠뜨리면 404가 난다
- [ ] 고객사 설정표에 행을 추가한다: 고객사, 상태 활성, 플래너 DB ID, 지침·참고자료 페이지 ID, 대상 유형, 워드프레스 주소, 고객사 유형, 회당 최대 처리 건수, (있으면) 유튜브 채널
- [ ] 워드프레스 고객사: 앱 비밀번호 발급, 브리지 플러그인 설치, ping 확인
- [ ] 클로드 코드 환경에 환경변수 두 줄(WP\_USER\_키, WP\_APP\_PASSWORD\_키 또는 BOARD\_ 쌍)을 넣고, 네트워크 허용 목록에 그 사이트 주소를 추가한다
- [ ] 자체 게시판 고객사: 클로드에게 `--board-inspect`로 관리자 화면을 떠서 `boards/<호스트>.json` 프로파일을 만들게 한다
- [ ] 클로드에게 썸네일 디자인을 정해 `designs/<고객사>.json`을 만들게 한다. 팀 레퍼런스 이미지가 있으면 파일로 건네준다
- [ ] 플래너에 숏폼 행 몇 개를 "시작 전"으로 만들고 15:00 루틴을 기다리거나 직접 실행해 원고가 들어오는지 본다
- [ ] 첫 발행은 `--draft`로 초안만 만들어 워드프레스에서 확인한 뒤 공개한다 (자체 게시판은 초안이 없으므로 더 조심)

**하지 않아도 되는 것.** 저장소에 고객사 설정 파일을 만드는 일, 루틴을 고치는 일. 발행 코드는 설정표의 활성 행을 전부 처리하므로 행만 추가하면 다음 회차부터 자동으로 포함됩니다.

**일시 중지.** 설정표의 상태를 "일시중지"로 바꾸면 모든 자동화가 그 고객사를 건너뜁니다.

## 12. 운영과 문제 해결

문제가 생기면 노션 실행 로그 표의 "상세" 칸부터 엽니다. 실패한 행은 플래너에서 "발행 오류" 상태가 되므로 눈에 띄고, 고친 뒤 컨펌 진행 중으로 되돌리면 다음 회차에 다시 시도합니다.

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| "발행 대상 고객사가 없습니다" | 설정표에 활성 행이 없거나 주소가 빔 | 설정표 확인 |
| 노션 404 또는 권한 오류 | 그 DB·페이지에 통합이 연결되지 않음 | DB ⋯ → 연결 → 통합 추가 |
| 워드프레스 401 (로그인 안 됨) | 앱 비밀번호 만료·오타, 또는 서버가 로그인 헤더를 지움 | 앱 비밀번호 재발급. 브리지 1.2.0 이상이면 보조 헤더로 복원됨. `/auth-probe`로 점검 |
| "워드프레스에 '…' 분류가 없습니다" | 플래너 카테고리 이름이 워드프레스와 다름 | 메시지의 실제 분류 목록대로 플래너 옵션 수정 |
| "슬러그 …가 이미 사용 중" | 같은 슬러그 글이 있음 | 플래너 슬러그 변경 |
| "이미지를 내려받지 못했습니다" | 노션 첨부 주소 1시간 만료 | 그대로 재실행 |
| "이미지 형식 변환 실패 … pillow-heif" | HEIC 사진인데 변환 라이브러리 없음 | `pip install -r requirements.txt` 후 재실행 |
| 보고에 "제한 모드" | 브리지 플러그인 없음 | 발행은 정상. 검색 설정을 사람이 채움 |
| "확정된 썸네일 디자인이 없습니다" | 디자인 파일 없음 | 9장 절차로 정해 굳힘 |
| "게시판 프로파일이 없습니다" | 새 자체 게시판 사이트 | `--board-inspect`로 떠서 프로파일 작성 |
| 게시판 로그인 실패, 스크린샷이 빈 화면 | 허용 도메인에 없음 | 환경 네트워크 허용 목록에 추가 |
| 게시판 "패스워드가 틀립니다" | 비밀번호의 기호가 환경변수 칸에서 상함 | `_B64`로 넣기 |
| 글에 네 바이트 이모지가 "?"로 | 게시판 DB 제한 | 코드가 자동 변환. 지침에도 규칙 있음 |
| 실행 로그에 아무 줄도 없음 | 로그 DB에 통합 미연결 | 로그 DB에도 통합 연결 (발행은 되고 로그만 조용히 실패) |
| 외부 사이트 인증서 오류 (unable to get local issuer) | 고객사 서버가 중간 인증서를 빠뜨림 | `certs/`에 그 인증서 .pem 추가. 검증을 끄지 않음 |

**안전 규칙 (절대 지키는 것).**

- 비밀값은 환경변수에만. 노션·저장소·루틴·보고에 절대 적지 않고, 화면에 찍지도 않습니다
- 발행 조건을 임의로 완화하지 않습니다
- 코드를 우회해 손으로 워드프레스·게시판에 올리지 않습니다. 노션 되돌려 쓰기와 로그가 빠져 다음 회차에 같은 글이 또 올라갑니다
- 원고는 노션에서 고칩니다. 발행 단계에서 본문을 임의로 고치지 않습니다
- 이미 붙은 썸네일, 이미 확정된 디자인 파일은 다시 만들지 않습니다
- 지침 8장 "출력 형식"은 고치지 않습니다
- 루틴 지시문을 바꾸기 전에 저장소 `routines/`에 이전 버전을 남깁니다
- 사람이 올린 글을 자동으로 수정·삭제하지 않습니다. 대량 수정이 필요하면 글마다 원본을 백업하고, 바뀌는 부분을 비교해 확인한 뒤 저장합니다

**코드를 고칠 때.** 테스트를 돌리고(`python3 -m pytest -q`, 네트워크 없이 돌아감), 깃허브의 기본 브랜치(main)에 합칩니다. 루틴은 main을 받으므로 다른 브랜치에만 올리면 반영되지 않습니다.
