# 마스터 시트 발행 로그 자동 기입 (Apps Script)

노션 콘텐츠 플래너에서 발행이 끝난 글을 고객사 마스터 시트 `7) 발행 로그` 탭에
옮겨 적습니다. 서버도 자격증명 파일도 없이 구글 안에서만 돕니다.

| 마스터 시트 | 노션 플래너 |
| --- | --- |
| 날짜 | 발행 예정일 |
| 콘텐츠 유형 | 유형 |
| 제목 | 제목 |
| 게재본 | URL |

---

## ⚠️ 마스터 시트에 붙이지 마세요

마스터 시트는 고객사와 공유하는 문서이고, 지금 공유 설정이 **`링크가 있는 모든
사용자 = 편집자`** 입니다. 시트에 붙는(바운드) 스크립트는 **그 시트를 편집할 수 있는
사람이면 누구나 열어볼 수 있습니다.** 노션 토큰을 거기 두면 링크를 아는 사람 전부에게
우리 노션 워크스페이스 접근 권한을 넘기는 셈입니다.

그래서 **우리 계정 소유의 독립 스크립트**로 만들고, 시트는 `openById` 로 열어 씁니다.
독립 스크립트는 만든 사람만 볼 수 있고, 시트에는 아무 흔적도 남지 않습니다.

---

## 설치 (한 번만, 5분)

### ① 스크립트 만들기

1. https://script.google.com 접속 → **새 프로젝트**
   (마스터 시트를 편집할 수 있는 구글 계정으로 로그인되어 있어야 합니다)
2. 프로젝트 이름을 `발행 로그 동기화` 정도로 바꿉니다.
3. `publish-log-sync.gs` 의 내용을 통째로 붙여넣습니다. (에디터의 기본 코드는 지웁니다)

### ② 노션 토큰 넣기

왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성 → 속성 추가**

| 속성 | 값 |
| --- | --- |
| `NOTION_TOKEN` | 노션 내부 통합 시크릿 (`ntn_...` 또는 `secret_...`) |

워드프레스 자동 발행에 쓰는 것과 같은 토큰을 그대로 쓰면 됩니다.

### ③ 플래너에 노션 통합 연결

플래너 데이터베이스 우측 상단 `⋯` → **연결** → 위 토큰의 통합을 고릅니다.
**이 단계를 빠뜨리면 "Could not find database" 오류가 납니다.**

### ④ 한 번 실행해서 권한 승인

에디터 위쪽에서 함수를 **`syncPublishLog`** 로 고르고 **실행**.
처음에는 권한 승인 창이 뜹니다 — *고급 → (프로젝트 이름)(으)로 이동 → 허용*.
("확인되지 않은 앱"이라고 나오는 건 정상입니다. 우리가 방금 만든 스크립트입니다.)

실행이 끝나면 **실행 기록**에서 몇 건이 들어갔는지 볼 수 있고, 시트에도 바로 보입니다.

### ⑤ 자동 실행 걸기

왼쪽 **⏰ 트리거 → 트리거 추가**

| 항목 | 값 |
| --- | --- |
| 실행할 함수 | `syncPublishLog` |
| 이벤트 소스 | 시간 기반 |
| 트리거 유형 | 일 단위 타이머 |
| 시간 | 오후 9~10시 (원고 발행 루틴이 끝난 뒤) |

이제 매일 알아서 돕니다.

## 고객사 추가하기

`publish-log-sync.gs` 위쪽 `TARGETS` 배열에 한 덩어리 더 넣고 저장하면 됩니다.

```js
{
  client: '고객사 이름',
  plannerDb: '노션 플래너 DB ID 32자리',
  spreadsheetId: '스프레드시트 주소의 /d/ 와 /edit 사이 값',
  sheetName: '7) 발행 로그',
  columns: { date: '날짜', type: '콘텐츠 유형', title: '제목', url: '게재본' },
  props:   { date: '발행 예정일', type: '유형', title: '제목', url: 'URL' }
}
```

- `columns` 는 그 시트의 헤더 문구, `props` 는 그 플래너의 속성 이름입니다.
  고객사마다 다르면 여기서 맞춰 주세요.
- 새 플래너에도 ③(통합 연결)을 해야 합니다.
- 새 시트도 그 구글 계정이 편집할 수 있어야 합니다.

## 동작 규칙

- **URL이 채워진 행**을 발행이 끝난 것으로 봅니다. 진행 상황은 보지 않습니다 —
  플래너마다 상태 이름이 다르고(`발행완료` · `게재완료`), URL이 적혔다는 것 자체가
  게재됐다는 뜻이기 때문입니다.
- 제목·유형·날짜 중 하나라도 비어 있으면 기입하지 않습니다. 사람이 플래너를
  채워야 하는 상황입니다.
- **덧쓰지 않습니다.** 제목과 게재본이 둘 다 빈 줄에만 씁니다. 유형만 미리 적어둔
  예정 줄이 있으면 그 줄부터 채우고, 다 차면 표 아래로 이어 붙입니다.
- **몇 번을 돌려도 같습니다.** 게재본 주소로 이미 적힌 것을 걸러내므로 같은 글이
  두 줄로 늘어나지 않습니다. 하루에 여러 번 돌려도 됩니다.
- 헤더는 `날짜 · 콘텐츠 유형 · 제목 · 게재본` 이 한 줄에 모두 있는 줄을 위에서부터
  찾습니다. 표가 몇 번째 줄에서 시작하든 상관없습니다.

## 고쳤을 때 확인

판정 로직은 구글에 올리지 않고도 확인할 수 있습니다.

```bash
node apps-script/test-publish-log-sync.js
```

실제 마스터 시트와 같은 모양의 표에 대고, 어느 줄에 무엇이 들어가는지만 봅니다.
시트·노션은 건드리지 않습니다.

## 오류가 났을 때

실행 기록(왼쪽 **실행수**)에 사유가 남습니다.

| 메시지 | 원인 | 대처 |
| --- | --- | --- |
| `스크립트 속성에 NOTION_TOKEN 이 없습니다` | ② 미완료 | 프로젝트 설정 → 스크립트 속성 |
| `노션 요청 실패 404 ... shared with your integration` | ③ 미완료 | 플래너 `⋯` → 연결 |
| `노션 요청 실패 401` | 토큰이 틀림 | 시크릿 다시 복사 |
| `'7) 발행 로그' 탭을 찾을 수 없습니다` | 탭 이름이 다름 | `sheetName` 을 실제 탭 이름과 맞춤 |
| `헤더 줄을 찾지 못했습니다` | 헤더 문구가 바뀜 | `columns` 를 실제 헤더와 맞춤 |
| `openById ... 권한이 없습니다` | 그 계정이 시트를 못 엶 | 시트 공유 확인 |

## 저장소의 파이썬 판(`notion-wp-publish/`)과의 관계

같은 일을 하는 경로가 둘 있습니다. **둘 중 하나만 쓰세요.**

| | Apps Script (이 폴더) | 파이썬 (`python -m notionwp.sheetsync`) |
| --- | --- | --- |
| 설정 | 구글 계정 하나, 5분 | 구글 서비스 계정 + 환경변수 |
| 실행 | 구글 시간 트리거 | Claude Code 루틴 |
| 코드 검토 | 구글 안 (저장소에 사본) | 저장소에서 바로 |
| 실행 로그 | 구글 실행 기록 | 노션 '자동화 실행 로그' DB |

둘 다 켜면 같은 글을 두 곳에서 기입하려 합니다. 중복은 걸러지지만 의미가 없으니
한쪽만 두세요.
